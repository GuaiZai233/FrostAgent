# ADR-0002：v1 数据库基线与固定模块无损协议

- **状态：** Accepted
- **日期：** 2026-11-14
- **替代：** [ADR-0001](0001-lossless-database-forward-compatibility.md) 的通用实施承诺
- **Maintainer 决策：** 直接重构数据库，已确认退休结构不另行归档。

## 决策

1. schema 18 是业务 v1 的关系基线，历史迁移数字不重置。删除旧模型目录 4 表、对话 scene/relation、记忆 visibility；不归档其退休值。现用共享模型目录、凭据、路由、记忆、聊天历史和其他有效数据保留。新库与升级库采用相同最终结构。
2. 兼容下限提高到 18，拒绝未适配旧程序；保护性拒绝不等于数据丢失。核心历史迁移序列继续用于升级；独立模块使用稳定 module migration ID，不冒充已验证的历史 checksum。
3. 固定实例模块表和 ZIP 信封承载不透明字节，校验模块 ID、记录 ID、格式版本、大小与 SHA-256。只有协议内独立模块获得未知格式的备份、恢复、再导出保证。未知 SQL 表、任意新增核心列或固定 JSON 键不自动获得保证。
4. 模块格式不可变；增加字段/语义时提升格式号。条件写必须匹配原格式和摘要，不允许降级覆盖。删除也是显式条件操作，禁止普通保存清空未知模块。
5. 恢复载荷默认禁用绑定，普通保存不能解除。执行方必须理解格式、验证数据并完成正常授权；通用存储不执行载荷。凭据继续留在受保护存储，不能依赖旧程序检查未知字节中的秘密。
6. 高核心版本但下限和实际布局允许时，完整操作可用。未知数据无法纳入协议时明确拒绝，不能静默遗漏。完整 SQL 备份使用一致快照；恢复失败纳入现有实例与共享目录回滚流程。
7. 今后核心字段废弃默认采用扩展、回填验证、停止旧写入、独立收缩迁移；移除时提高下限。本次不归档仅授权已列明退休对象。模块独立于核心实体；若要承载实体字段，必须先定义所有权、删除和 ID 复用语义。

## 范围与验证

逻辑实例 ZIP 继续按已有安全规则排除秘密，不代替完整数据库灾备；例如 Computer Use 桥绑定和任务执行状态仍按其专用恢复规则处理。字节无损指固定模块信封内的数据，不包括已获准删除的退休值或原本不导出的秘密。

验收覆盖 SQLite/PostgreSQL 的现用数据迁移、清理失败回滚、未知格式写保护、同 ID 跨实例隔离、摘要/重复项拒绝、恢复绑定保持和实例删除。跨版本驱动使用固定历史二进制与独立未来模块生产者验证完整往返。详见[版本兼容说明](../version-compatibility.md)和[实现白皮书](../../.frostagent/whitepaper/storage-compatibility.md)。
