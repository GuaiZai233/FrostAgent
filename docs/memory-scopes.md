# 记忆作用域

记忆按实例内的用户作用域、群作用域隔离，不再区分 public/private 可见性。存储和管理 API 中的 `private` 表示用户作用域类型，不表示可见性开关。

| 对话                   | 写入、自动提取、compact 提炼 | Bot 可读取的长期记忆 |
| ---------------------- | ---------------------------- | -------------------- |
| 与用户 U 私聊          | 用户 U                       | 用户 U               |
| 用户 U 在群 G 触发轮次 | 群 G                         | 群 G 和用户 U        |
| 群 G 的定时轮次        | 群 G                         | 群 G                 |

用户身份来自平台适配器验证的本轮发送者。昵称、@、引用消息的作者和模型提供的参数都不能授权读取其他用户的记忆。QQ、OneBot、AstrBot 的 QQ 身份沿用相同的用户作用域；其他平台仍按平台命名空间隔离。

`memory` 工具的 `search`、`list` 支持 `scope`：

- `current`（默认）：本轮允许读取的全部作用域。
- `user`：只读取本轮发送者的用户作用域。
- `group`：只读取当前群作用域，私聊不可使用。

工具不能指定任意用户 ID 或群 ID。群聊中的 `write` 始终写入当前群，`scope: "user"` 也不会改变写入位置。群记忆不再区分成员 owner，来源消息和发送者保留为溯源信息。

## 旧数据与数据库兼容

数据库 schema 维持 v16，不执行新 migration。SQL 中的历史 `visibility` 列保留以维持现有结构，业务模型、导入导出和管理 API 已删除该字段。旧 JSON 中的字段会被忽略，旧 protobuf 字段编号保留为 reserved，不能被新字段复用。

旧用户记忆保留原用户作用域；旧群记忆保留原群作用域，读取时统一呈现为群所有。旧 `public` 不授予额外访问权限，也不会把群记忆转移到旧 owner 的用户作用域。此次不提供掩码功能。
