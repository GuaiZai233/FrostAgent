# 上下文自动压缩

群聊和私聊都支持后台自动 compact。私聊会把较早的消息与已有摘要重新总结，保留最近一轮原始对话；后续请求携带更新后的摘要和最近消息。

- 在模型路由中使用「上下文压缩」工作负载选择模型。禁用此工作负载也会禁用私聊压缩。
- `GROUP_COMPACT_BUFFER_SIZE` 同时控制群聊和私聊的自动压缩批量阈值，默认 20 条消息。私聊不计已有摘要，并为最近一轮预留空间；历史上限较小时会降低实际阈值。
- `GROUP_COMPACT_MIN_INTERVAL` 同时控制同一群聊或私聊两次自动压缩的最短间隔，默认 `30s`。冷却期间选中的批次会保留到后台请求执行。
- `MAX_CONTEXT_MESSAGES` 继续限制私聊历史条数，摘要占两条。慢请求、失败重试和禁用压缩时也遵守此上限；溢出的最旧原消息可能被裁剪。
- `GROUP_COMPACT_MAX_BUFFER_SIZE` 只控制群聊积压缓冲，不改变私聊历史上限。
- 群聊 compact 白名单仅影响群聊，私聊不受该白名单限制。模拟直聊不自动触发压缩。

压缩失败不会提交新摘要；历史仍按条数上限裁剪，仍有可压缩消息时会在冷却后重试。重置会话会使旧的在途摘要失效。

管理员仍可在私聊发送 `/compact` 立即压缩当前历史。手动与自动压缩共用同一会话的执行互斥。私聊摘要沿用已有手动压缩的会话内存储方式，实例重启或会话过期后不会恢复；长期记忆仍由记忆功能管理。
