# Token 用量统计

主页在「资源」上方展示当前实例自功能启用后的累计用量。统计按实例持久保存，重启保留，不回填旧调用。

## 统计口径

- 按对话、子智能体、多模态理解、群聊摘要、表情包摘要、记忆提取、记忆整理、向量化和安全分类分别累计。
- 使用 OpenAI 兼容 API 的 `usage` 字段；支持 `prompt_tokens_details.cached_tokens` 和 DeepSeek 的 `prompt_cache_hit_tokens`。
- 缓存 Token 是输入 Token 的子集，不重复加入合计。命中次数指 API 报告缓存 Token 大于零的请求数；返回零表示确认未命中。
- 省略、null 或负值记为 `unestimated`，不按字符数猜测。已知输入与输出都存在时可相加得到合计。嵌入调用的输出为零。
- 同时显示已知数量和缺失请求数，避免把部分已知误当作完整统计。多模态一栏是理解请求的完整用量，无法从 API 未提供的信息中单独拆分图片或文本。
- 已成功解析的 HTTP 成功响应会记账，即使后续内容、向量或表情包结果校验失败。网络失败、HTTP 错误、无法解析的响应无法获知消耗，不计入成功响应数。
- 全局共享模型目录的连通性测试没有实例归属，不计入实例统计。

## 保存与恢复

SQL 使用现有 `settings` 表的独立 `token_usage` scope，每个模块一行，不增加数据库 migration；旧文件运行模式使用实例目录的 `token_usage.json`。统计不包含提示词、消息内容、用户标识或密钥。

完整实例 ZIP 包含 `token_usage.json` 并在恢复时保留累计值；配置导出与配置复制不携带用量。缺少该成员的旧备份仍可恢复，从零开始统计。实例删除会同时清理统计。

记账失败会写入日志并在概览显示「累计数据可能不完整」，同时尽力立即保存缺失标记。若存储完全不可写，数据和标记都可能无法跨重启保留。统计失败不会改变模型响应或计费结果。旧文件模式的统计文件损坏时保留原文件，记录日志并停用本次运行的统计，概览显示 `unestimated`；实例仍可正常启动。

此功能仅保证当前及后续支持该统计格式的版本保留数据；旧版程序导出的备份不包含用量。
