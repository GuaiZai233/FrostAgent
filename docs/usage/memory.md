# 记忆管理

FrostAgent 用长期记忆保存值得在后续对话中召回的信息，同时使用会话历史和群摘要维持短期连续性。长期记忆与群摘要不是完整聊天记录。

## 记忆如何形成

- 从私聊对话中自动提取，按实例配置的累计轮数批量执行。
- 从群聊压缩快照提炼长期信息。
- 用户通过对话明确要求记住内容，由工具和可信会话上下文处理。
- 管理员在控制台维护条目，或执行反思整理。

记忆提取和反思依赖模型路由器中的相应工作负载。自动提取默认最小累计 3 轮、最大累计 5 轮；调整后应在真实会话中验证，不使用模拟连接测试持久化写入。

## 作用域与归属

| 场景                       | 边界                                                    |
| -------------------------- | ------------------------------------------------------- |
| 私聊                       | 按用户隔离，只在当前实例的对应用户作用域召回            |
| 群聊                       | 按实例、规范化平台和群 ID 隔离，不走公开 / 私有共享路径 |
| 群内个人自述               | 使用可信发送者的 QQ 归属；昵称和群名片是展示信息        |
| 第三方说法、群规、多人关系 | 归入群作用域，不能仅凭提到某个人就归到其个人名下        |

同一个人出现在两个群中，不意味着两群记忆自动共享。群名片也不能直接变成 Bot 对该人的称呼。

## Embedding 语义检索

当前版本提供可选向量检索，默认关闭。在模型路由器配置独立 `embedding` 路由，再到「Bot 服务端设置 → 记忆设置」打开「启用Embedding」（`ENABLE_EMBEDDING=true`）。

启用后按向量相似度检索，Bot 自动召回和工具搜索最多取 20 条，网页继续分页；原有标签、记忆提取、摘要与反思保留。工具搜索可提供自然语言 `query` 或 `tags`，同时提供时优先 `query`。作用域仍按实例、私聊用户与群隔离。

SQLite 的向量只存在内存，进程重启后后台重建。PostgreSQL 需要部署者预先安装 pgvector 并在目标数据库启用 `vector` 扩展，否则不能开启；FrostAgent 不代为安装扩展。关闭功能恢复关键词检索，并保留 PostgreSQL 中兼容的向量。首次启用、缺失或不兼容的索引会后台重建，等待期间会提示索引尚未就绪。

应用导出和 ZIP 不携带向量，恢复后根据记忆与有效模型路由重建。完整启用步骤、索引更新与排障见[Embedding 语义检索](./embedding)。

## 来源与图片

记忆可以保留原文、展示摘要、证据、源消息 ID 和源发送者 ID。摘要帮助阅读，原始证据用于核对。

来自图片识别的条目保留图片来源标记，显示「（原source为图片形式）」。图片中的第一人称文字不等于上传者的自述，也不能把图片识别结果作为用户亲口说过的话。

## 控制台操作

在「记忆管理」中检索条目、查看归属与来源，按页面提供的编辑和删除操作纠正错误。检查群档案和反思归档时，确认当前实例与群 ID。

反思会整理或合并记忆；合并来源保留在归档中，归档不参与正常检索注入。群摘要用于最近话题延续，新摘要不作为普通长期记忆条目写入。

发现错误记忆时，先核对证据，再修正或删除。清理会话不会自动删除所有长期记忆；长期记忆修改也不会自动重写历史消息。

## 群成员称呼

在群档案中按成员 ID 编辑优先称呼和别名；清空优先称呼后恢复使用 QQ 昵称。称呼只改变展示和上下文，不改变成员身份、管理员权限或记忆归属，也不会跨平台、跨群同步。

用户可以在真实群聊中要求 Bot 记住称呼，模型通过 `memory` 的 `set_member_name` 操作更新本群已观察到的成员。省略 `user_id` 时使用当前发送者的可信 ID，显式指定时也只允许当前群已观察成员；空 `preferred_name` 清除优先称呼。模拟会话不能持久化修改。

反思也可基于本群明确的原始证据补充已观察成员的称呼，不会只凭群名片推断。若称呼错误，核对原始证据后在群档案修正。

## 备份与导入

使用「系统设置 → 备份与还原」下载 `memory.json`，或下载包含记忆、档案、归档的全量 ZIP。记忆导入按 ID 合并，同 ID 跳过，现有群档案优先；不同 ID 仍可能表达相同内容，需要人工查重。

当前运行时使用 SQL，旧 `agent export/import/list/stats` 命令只操作 JSON 文件，不能作为当前数据库的备份工具。
