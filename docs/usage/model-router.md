# 模型路由器

模型路由器把「连接哪家服务」「使用哪个模型」「哪个工作负载使用它」分开配置。

## 三层配置

| 配置              | 内容                                         | 范围             |
| ----------------- | -------------------------------------------- | ---------------- |
| 供应商 / Endpoint | API 基地址、凭据来源、启用状态               | 所有实例共享     |
| Model             | Endpoint、上游模型名、显示名与能力标签       | 所有实例共享     |
| Binding           | 为工作负载选择 Model、跟随主对话、继承或停用 | 实例默认与群覆盖 |

界面修改先进入草稿，点击发布后生效。供应商、模型和密钥草稿为共享资源；重置共享草稿也会丢弃其他页面尚未发布的相关修改。

## 添加供应商与模型

1. 打开「模型路由器」，添加 Endpoint，输入显示名称和 API 基地址。
2. 选择凭据来源并配置密钥；无鉴权服务可使用空 Key。
3. 添加 Model，选择所属 Endpoint，填写服务实际接受的上游模型名。
4. 按模型实际能力配置标签，测试请求。
5. 在「实例默认路由」选择主对话模型，配置其他工作负载，发布。

API 基地址会与 `chat/completions` 拼接。例如服务接口是 `https://api.example.com/v1/chat/completions`，基地址填写 `https://api.example.com/v1`。界面的「获取名称」依赖上游提供模型列表；无法获取时可以手动填写模型名。

## 工作负载

| 界面名称       | 键               | 作用                           |
| -------------- | ---------------- | ------------------------------ |
| 主对话         | `dialogue`       | 聊天与主工具循环               |
| 子 Agent       | `subagent`       | 委派子任务                     |
| 多模态（图片） | `vision`         | 图片描述与理解                 |
| 反思           | `reflection`     | 记忆反思、安全网关使用的路由   |
| 记忆提取       | `memory_extract` | 从对话或群压缩结果提取长期记忆 |
| 群聊压缩       | `group_compact`  | 群聊滚动摘要与上下文压缩       |
| Embedding      | `embedding`      | 记忆向量索引与语义检索         |

当前提供以上七类工作负载；Embedding 按[语义检索指南](./embedding)配置，不能用普通聊天模型路由替代。

使用界面提供的绑定模式：指定模型、跟随主对话、群级继承实例默认、或停用。主对话不能跟随自身；反思路由不提供停用选项。其他工作负载停用后，相应功能会拒绝或跳过执行，不会自动使用随机模型兜底。

首次配置可以复用同一个模型完成多个工作负载，再按能力和费用拆分。图片模型必须实际支持图片输入；工具调用能力也需要上游和模型支持，添加标签本身不会赋予能力。

Embedding 模型需要实际支持 OpenAI 兼容 `/embeddings` 接口，标记 `embedding` 能力并单独绑定。实例默认路由可以指定模型或停用；群级可以继承默认或指定模型，不能选择停用或「跟随主对话」。实例还需开启 `ENABLE_EMBEDDING` 才使用向量检索。模型的「最大输入 Tokens」可选，用于约束记忆处理请求的输入副本，完整存储原文不受截断影响。

## 群级覆盖

进入「群级覆盖」，按规范化平台与群 ID 配置差异。未覆盖的工作负载继承当前实例默认值，私聊使用实例默认路由。QQ 的 OneBot 与 AstrBot aiocqhttp 接入归一化为 `qq` 平台，群号需填写同一个实际群 ID。

某群切换主对话模型时，配置为「跟随主对话」的其他工作负载也会跟随该群的有效主对话模型；绑定到固定模型的工作负载保持固定选择。

群会话的模型配置面板会保留模型选择和操作入口。排查时核对面板中的工作负载、绑定模式与有效模型，修改草稿后仍需发布。

## 凭据来源

当前 SQL 模式支持手动输入、Secret 文件和 Windows Credential Manager，禁止供应商使用进程环境变量（`env`）作为凭据来源。文件来源需要服务账号能够读取文件，Windows 凭据来源需要同一运行账号访问凭据。

手动密钥保存在数据库的凭据存储中。Web DTO 展示配置状态，应用层备份会置空密钥和凭据来源；迁移后需要检查并重新设置。共享凭据的修改影响所有使用对应 Endpoint 的实例。
