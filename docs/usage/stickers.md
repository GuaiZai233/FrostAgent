# 表情包

「表情包摘取」管理实例的贴图库。后端可以观察支持的聊天图片、生成描述，再由模型检索并通过 `send_sticker` 工具投递。图片理解依赖可用的视觉模型。

## 管理贴图

选择实例后查看贴图、描述和召回次数，按页面提供的操作维护条目。召回次数表示检索使用的权重，不等于成功发送次数。贴图信息和原始图片可以通过贴图 ZIP 或全量存档备份。

贴图发送需要库中存在可用贴图、适配器可读取图片且返回投递结果。AstrBot 跨容器时应正确设置 `http_base_url` 并使用支持回执的新版插件。

## 表情包积极度

`STICKER_ACTIVITY` 默认 `0`，禁用表情包发送。值为 1～10 时，约束间隔为 `(11 - 积极度) × 5`。

| 积极度 | 间隔     |
| ------ | -------- |
| `0`    | 禁用发送 |
| `1`    | 50       |
| `5`    | 30       |
| `10`   | 5        |

计数模式由 `STICKER_ACTIVITY_MODE` 选择：

- **`bot_turns`（默认）**：每次被触发的 Bot 对话记一轮，包括触发后选择静默的主动对话。工具循环和发送消息条数不算新的对话轮次。
- **`all_messages`**：按真实传入聊天消息计数，包括不唤醒 Bot 的消息；协议心跳和通知不属于聊天消息。计数本身不会触发回复。

计数按实例维护。成功投递贴图后重置计数，改变积极度或模式也会重置。达到间隔时后端要求模型在回复前选择贴图；场景不适合时，内部宽容机制可以临时放宽约束，避免为了计数强行发送不合适内容。

## 排查发送失败

- 积极度为 0 时，工具返回「表情包发送功能已被禁用，请管理员在 FrostAgent 后端启用此功能。」。
- 没有合适贴图时，先检查库与描述，不把普通图片自动当作目标贴图。
- AstrBot 提示更新插件时，检查投递回执能力。
- 获取图片失败时，核对 HTTP 根地址、网络、图片接口和当前实例。

`all_messages` 只统计后端实际收到的消息；AstrBot 关闭普通群消息转发后，不会统计未上报的消息。模拟会话跳过后台贴图摘取。
