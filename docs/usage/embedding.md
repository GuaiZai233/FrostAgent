# Embedding 语义检索

Embedding 将记忆内容与查询转换成向量，按语义相似度召回相关条目。它是可选的实例功能，启用后仍保留原有标签、摘要、提取和反思流程。

::: tip 版本范围
本页适用于包含 [#194](https://github.com/GuaiZai233/FrostAgent/pull/194) 更新的版本。未包含该更新的版本没有 Embedding 路由和「启用Embedding」开关，应使用既有关键词检索。
:::

## 启用步骤

1. 准备实际支持 OpenAI 兼容 `/embeddings` 接口的模型服务。
2. 在共享模型目录添加对应 Endpoint 和 Model，填写上游模型名，标记 `embedding` 能力；能力标签不会把聊天模型变成向量模型。
3. 选择实例，在「实例默认路由」为「Embedding」指定模型并发布。它是独立路由，不能跟随主对话。
4. 使用 PostgreSQL 时，先按下一节为目标数据库准备 pgvector。
5. 打开「系统设置 → Bot 服务端设置 → 记忆设置」，开启「启用Embedding」。对应配置为 `ENABLE_EMBEDDING=true`，保存后自动应用。
6. 等待已有记忆的后台索引重建，再在「记忆管理」用自然语言搜索，并在真实对话中核对召回结果。

群级路由可以继承当前实例默认 Embedding 模型，或单独指定；不允许群级停用或跟随主对话。所有向量和召回仍遵守实例、私聊用户和群作用域，不因为共享供应商而共享记忆。

## SQLite 与 PostgreSQL

| 后端       | 向量生命周期               | 前置条件                                        |
| ---------- | -------------------------- | ----------------------------------------------- |
| SQLite     | 只存内存，进程重启后重建   | 不需要数据库向量扩展                            |
| PostgreSQL | 向量持久化，兼容索引可复用 | 部署者预先安装 pgvector，并在目标数据库启用扩展 |

PostgreSQL 管理员先按 [pgvector 安装说明](https://github.com/pgvector/pgvector#installation)安装适配部署环境的扩展，再在 FrostAgent 使用的目标数据库执行：

```sql
CREATE EXTENSION vector;
```

扩展需要按数据库启用，仅在其他数据库中安装不满足条件。可检查：

```sql
SELECT extname FROM pg_extension WHERE extname = 'vector';
```

FrostAgent 不执行扩展安装；缺少 pgvector 时开启操作会报错。未启用 Embedding 的普通 PostgreSQL 运行不依赖它。SQLite 页面会提示向量不持久化，这是当前存储方式，不代表长期记忆原文没有保存。

## 召回与更新

- Bot 自动召回和 `memory` 工具向量搜索最多取 20 条，控制台搜索继续按原分页方式显示。
- 工具接受自然语言 `query` 或 `tags`，同时提供时优先 `query`；只有标签时用标签组合生成向量查询。
- 已有消息窗口提取 / 反思完成后更新受影响索引，首次启用、索引缺失或模型不兼容时后台重建。
- 模型、端点或返回向量维度变化可能导致索引失效；重建未完成时提示「向量索引尚未就绪」。

索引未就绪或向量召回失败时，Bot 记录警告并继续当前对话，该轮可能没有长期记忆注入；工具和网页搜索会报告错误。开启状态下不会静默改用关键词检索，关闭 `ENABLE_EMBEDDING` 才恢复关键词路径。

重建和查询会调用外部模型 API，也可能触发反思与摘要请求；按实际供应商费用和数据发送范围配置。派生向量不会替代原始记忆证据或改变归属规则。

## 输入限额

模型编辑中的「最大输入 Tokens」可选，填写非负整数；留空或 0 不设置本地预算。当前实现使用保守 UTF-8 字节预算截断请求副本，不进行该模型的精确 Token 分词，数据库中的完整原文保留。

未设置预算或预算仍不满足上游要求时，明确的输入长度拒绝会让本次相关处理跳过；对于过长的记忆向量输入，可跳过该条而继续其余条目。检查上游限制和日志后调整模型预算，不通过删除原始记忆来绕过限制。

## 关闭、备份与迁移

关闭「启用Embedding」恢复关键词检索，不删除兼容的 PostgreSQL 向量。应用层 JSON 导出和全量 ZIP 都不携带向量；还原后配置模型与凭据，再开启功能重建。SQLite 重启后的重建也需要模型服务可用。

包含该更新的版本使用 Schema v12 保存输入限额和摘要待刷新标记，SQL 升级仍遵守[迁移规则](../operations/upgrading)。数据库级完整备份与应用导出用途不同，参见[数据库与备份](../operations/storage)。
