# 设置与生效方式

「系统设置 → Bot 服务端设置」使用中文表单管理 SQL 配置。先确认当前实例；监听、沙箱、安全模式、管理令牌等全局设置会影响整个服务。

## 编辑、保存与还原

1. 修改开关、数值、列表或文本；修改先进入本页草稿。
2. 页面顶部出现红色未保存提示后，点击「保存」统一提交。
3. 点击「还原」丢弃草稿，恢复已保存的配置；离开页面也会丢弃未保存更改。
4. 检查保存结果、实例状态和日志，确认运行时应用成功。

系统提示词、Bot 名称和唤醒别名在[人格设定](./persona)中编辑；供应商凭据和各任务的模型选择在[模型路由器](./model-router)中维护。模型路由器有自己的草稿与发布流程。

## 灰色默认值与继承

输入框内的灰色占位描述清除当前值后的有效默认或继承来源，不是已经填写的自定义值。留空后保存会清除当前覆盖，使用默认值或继承值；不需要另找删除按钮。

开关可以表达继承或默认状态，按旁边的实际状态说明核对。部分默认值依赖其他参数，例如记忆提取轮数上限不小于下限，群压缩积压上限取决于每批条数。既有实例以 SQL 中已保存的值为准。

「保留消息条数」要求至少 4；新实例模板写入 20，清除该覆盖后使用运行时代码默认 50。它不是模型的 Token 上限。

## 保存后何时生效

| 配置类型                 | 行为                                                                           |
| ------------------------ | ------------------------------------------------------------------------------ |
| 页面标注支持热更新的设置 | 保存后由控制面或运行时读取新值；例如群回复策略、Bot 用户列表、ActionsCat 开关  |
| 需要重建实例的设置       | 保存后自动重新装配运行时，可能中断连接和在途任务；内存会话会尝试转交给新运行时 |
| 管理监听地址             | 保存后尝试重新绑定；地址改变后从新地址打开页面，失败时检查回滚与日志           |
| 额外 env 注入项          | 保存到数据库，重启整个 FrostAgent 进程后才生效                                 |

普通实例配置无需额外手动重启进程。应用失败时检查页面错误和日志，不能仅凭输入框显示了新值判断生效。容器构建还会校验管理监听的回环隔离，见[Docker 部署](../guide/docker)。

## Bot 用户列表

在「Bot 行为与回复策略」的 Bot 用户 ID 列表中逐项添加、删除已知 Bot。单个 ID 适用于所有平台，`platform:ID` 可限定平台。保存后统一应用，配合连续对话轮数和 `soft` / `hard` 策略防止循环，详见[群聊策略](./group-chat#限制-bot-互相循环)。

## 额外 env 注入

页面底部的额外 env 注入用于需要读取进程环境的外部组件，支持添加、修改和删除。它不替代常规 SQL 设置，也不能覆盖已由结构化表单管理的设置键。

保存或删除后重启 FrostAgent。宿主环境已有的同名变量优先；移除注入项不会移除宿主环境变量。**全局设置 JSON 会明文携带 `extra_env` 的值**，导出文件可能含外部组件凭据，应按敏感备份保存，分享前逐项移除。

全部键名、范围和约束见[配置参考](../reference/configuration)。
