# 错误 UUID 与日志定位

Bot 的系统错误统一使用单行格式，只包含主要错误类型、安全摘要和 UUIDv4，例如：

```text
[FrostAgent 错误] LLM 响应失败：上游 HTTP 400 (Ref_ID: f08fb287-2c99-4339-bd83-606d2caf6699)
```

LLM、上下文超限、计费、安全拦截、工具执行和消息处理错误均使用此格式。`Ref_ID` 即日志中的错误 UUID。

端点地址和底层错误原文保留在日志详情中。每条 ERROR 日志拥有独立的错误 UUID，查询不会混淆同一会话中的多次报错。

## 控制台查询

进入「日志查询」，选择对应实例与日志来源，在顶部「按错误uuid定位」输入 UUID。定位会忽略当前分页和级别/来源过滤，选中目标日志并直接打开详情。

UUID 仅能查询所选来源中仍保留的日志。日志清理、缓冲区覆盖或实例重启后，旧日志无法查询；此功能不增加磁盘持久化。

## Bot 指令

配置在当前实例 `ADMIN_QQ_IDS` 中的管理员可发送：

```text
/log <uuidv4>
/log
```

私聊中，所有管理员指令（`/reset`、`/ban <userID>`、`/unban <userID>`、`/compact`、`/reflect`、`/log [uuidv4]`）均可直接输入，无需 @ Bot。默认前缀为 `/`，也支持 `ADMIN_COMMAND_PREFIX` 配置的前缀。群聊中，`log` 无需 @ Bot，其他管理员指令仍需真实 @ Bot。所有管理员指令仍仅限当前实例配置的管理员使用。

省略 UUID 时，仅当同一群聊或私聊中紧邻的上一条消息是 Bot 的报错输出，才自动使用其中的 `Ref_ID` 查询。中间有其他消息、上一条不是 Bot 报错或没有可用记录时，直接输出管理员指令目录。此判断独立于聊天历史采集配置，仅保留当前连接中的临时 UUID，重新连接后需显式提供 UUID。

Bot 输出需收到平台成功回执后才会更新相邻消息状态；发送失败或回执超时的输出不会成为查询目标。紧接发送输入 `/log` 时，会先等待该输出的回执结果。

- 私聊执行时，Bot 直接回复错误 UUID、时间、日志分类和详细错误。
- 群聊执行时，详细错误私聊给执行指令的管理员，群内只提示发送结果。
- 私聊失败或无法确认送达时，群内提示改用私聊查询，不会在群内发送错误详情。
- 非管理员无法查询；UUID 只能定位当前实例的错误日志。
