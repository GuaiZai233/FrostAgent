# 聊天原文档案

聊天档案保存平台收到的当前消息及机器人发送的消息，供 search_chat_history 工具按关键词查询。它与提炼记忆、会话上下文、摘要、compact 分别维护；重启后查询档案不会恢复或自动注入历史上下文。档案不参与 Embedding。

## 采集范围

在实例的「Bot 服务端设置 → 聊天记录」配置：

- 私聊默认开启，CHAT_HISTORY_PRIVATE_ENABLED=false 可停止新增记录。
- 群聊始终实行白名单制，CHAT_HISTORY_GROUP_WHITELIST 默认为空。
- 白名单用英文逗号分隔。QQ 可直接填写群号；其他平台使用 platform:group:id，例如 telegram:group:synthetic-group。QQ 的 qq、onebot 前缀视为同一平台。
- 白名单群中，即使消息未唤醒机器人、模型路由关闭或机器人保持沉默，也会采集系统收到的当前消息。
- 修改白名单、关闭私聊持久化只停止后续采集。已有档案继续保留，并可在同一实例、同一平台、同一群聊或私聊中检索。
- 模拟 Direct Chat 不采集，也不能查询真实档案。不会导入上游打包携带的整段旧上下文。
- 保存文本原文、发送者、平台消息 ID、时间及回复关系。媒体保存类型占位，不下载或保存附件字节、临时下载地址和图片识别描述。

## 检索

search_chat_history 接受 1～6 个关键词，按原文子串匹配，英文不区分大小写；默认 all 要求一条消息包含全部关键词，any 表示任一命中。支持携带时区的 RFC3339 时间区间和最多 20 条结果，结果按时间倒序返回。

查询范围由后端当前会话身份决定，模型不能指定其他群或用户。长消息返回命中附近的原文片段，带 truncated 标记；每次工具输出有字符预算，数据库保留完整原文。历史文字应作为不可信资料处理。

received 表示入站消息；delivered 表示上游确认投递成功；sent 仅表示写入了传输连接，尚无平台确认。生成但未发送、已知发送失败的回复不记录为已送达。

## 持久化与故障

档案位于现有 SQLite / PostgreSQL 数据库中的独立 chat_history 表，迁移到 schema v17。旧程序不应通过修改版本号打开 v17 数据库。

写入通过容量 64 条的有界队列异步执行；每条记录至多重试 3 次，单次数据库操作限时 1 秒。队列满、记录超过 1 MiB 或重试失败时告警并跳过，聊天继续。告警不包含原文。正常停止给队列最多 2 秒的排空时间。

保证已提交记录在数据库正常持久化保证内可恢复；断电可能丢失尚未提交的数据。原文不依赖 compact 成功或进程正常退出才保存。稳定平台消息 ID 用于入站去重；没有消息 ID 时按独立消息记录。

## 备份

实例完整 ZIP 增加 chat_history.json，恢复时还原原文。旧备份没有此文件时仍可正常恢复。原文包含个人聊天内容，应妥善保管备份；单独导出记忆不包含聊天档案。删除实例时，通过数据库外键一并删除其档案。
