# 数据库 v1 基线与无损兼容

当前数据库核心 schema 为 **20**，不是将历史版本重置为 1。规范见 [ADR-0002](adr/0002-v1-database-baseline.md)。本页区分原位升级、逻辑实例备份与未来模块兼容。

## v1 清理

从 v7–v19 按历史迁移升级；v20 在一个事务内删除以下已停用结构，并将兼容下限提高到 20：

| 删除对象 | 当前数据去向 |
| --- | --- |
| `models`、`model_endpoints`、`model_secrets`、`endpoint_ids` | v11 已转换到共享 `provider_*`；v20 保留现用目录、路由和凭据，不重新导入旧副本 |
| `dialogues.scene`、`dialogues.relation` | 对话只使用 ID、用户内容和推荐回复 |
| `memory_entries.visibility` | 权限由记忆 scope、owner 和 gateway 判定，不依赖该字段 |

Maintainer 已明确选择**不归档这些退休值**。因此不能称这次删除保留了所有历史字节；无损保证针对现用数据及协议内模块。迁移失败会回滚 v20 的 DDL、模块登记、版本与下限；更早已提交的迁移不一并回滚。新建库直接使用清理后的定义。

旧 v15–v19 程序不能直接使用清理后的库。返回旧程序应恢复升级前的数据库备份；不得手工降低版本标记。实例 ZIP 会按既有规则排除凭据，不是数据库灾备副本。

## 未来模块如何无损

固定 `module_payloads` 表以 `(instance_id, module_id, record_id)` 标识独立实例模块记录，保存格式版本、原始字节的 base64、SHA-256 和恢复绑定状态。固定 `modules.json` 信封随完整实例 ZIP 导出。程序不需要认识模块或其内部格式，就能校验、保存、恢复并再次导出相同字节。

- 普通创建不覆盖已有记录；更新必须匹配原格式和摘要，并拒绝格式降级。没有清空模块再批量替换的接口。
- 恢复一律设置 `requires_rebind=true`，普通保存不能清除它。模块理解格式、验证数据并完成自身授权后，才可显式重新绑定。载荷本身不会触发执行。
- 删除实例通过外键清理全部协议模块；单记录删除也必须匹配格式和摘要。
- 完整 SQL 导出使用同一个只读事务快照。恢复前验证重复 ID、格式号、摘要和大小；写入失败进入实例恢复的原有清理流程。
- 载荷每条最多 32 MiB，每实例最多 128 MiB、10,000 条；完整 ZIP 仍受 512 MiB 限制。
- 模块只允许写入可备份数据。凭据留在受保护的凭据存储；通用层不能判断任意不透明字节是否含秘密。
- 此协议用于独立实例模块。它不是核心行的任意字段 sidecar；依附某条记忆/对话的扩展必须另行定义实体身份、删除和 ID 复用规则。

## 操作门禁

完整备份、恢复、删除不再仅因 `version` 较高而拒绝。必须同时满足兼容下限、已知核心与载荷表的结构/约束，以及未知 SQL 模块保护。

任意额外核心列、未知约束、危险依赖、触发器、PostgreSQL rule/RLS 等仍会被拒绝。有数据的未知 SQL 表，以及未纳入协议的跨 schema 实例依赖，也不能作为完整实例导出或删除。未知 ZIP 成员仍拒绝；未来模块应放进固定的 `modules.json`，不新增任意成员来绕过校验。

任意核心 JSON 新键不在自动无损保证内。旧业务写入器仍可能按已知类型重写 JSON；改变这类结构必须先发布保留式读写器并配对测试，或提高兼容下限。

## 以后追加或废弃字段

1. 独立新功能优先使用固定模块载荷，新增格式字段/语义时提升该模块格式号；迁移使用稳定、不可变 module ID。旧程序仅透传，不能以旧格式覆盖新格式。
2. 核心关系字段变更追加不可变迁移，先扩展、回填并验证读写；只有已证明旧写入器安全时才保留兼容下限。不能因为字段可空就假定安全。
3. 废弃字段先停止读写，核对数据依赖和凭据去向，再在明确的结构边界删除、提高下限。是否归档由 Maintainer 决定。本次不归档只适用于上表，不是未来自动删除授权。
4. 模块升级用原格式/摘要条件写入；模块卸载逐条条件删除或随实例删除。未知格式保留，避免“全表替换”。

- 历史 v15 修补版 `409e50b5262ea3324f092560ee0cdcf206f93a1f` 与 v16 `ef4789988b3ec06ce26f0a050443cb379204939f` 的配对往返测试保留。这不表示它们能打开 v20。

- [迁移回归](../internal/storage/schema_v1_test.go)、[模块回归](../internal/storage/module_payloads_test.go)、[快照回归](../internal/storage/snapshot_test.go)、[实例生命周期](../internal/instance/module_payloads_test.go)覆盖现用数据、条件写、绑定状态和清理。PostgreSQL 测试在 Linux CI 的真实数据库运行；未设置测试 DSN 时仅为跳过。

采用本协议的程序之间才有这些保证；不承诺任意未来 SQL 结构、未知固定 JSON 语义或多进程混合写库。
