# 会话与日志持久化

## 保留与恢复

真实会话在状态发生变化时保存检查点。重启后恢复已有检查点，继续使用最近消息和已提交摘要；不会从聊天原文档案重建上下文。Direct Chat 模拟会话不保存。

检查点包括私聊历史、群聊已准入的消息缓冲、摘要及最近一批压缩来源、模型和 Prompt 信息、最近一次实际模型请求（包含请求已有的内联图片）。「会话与 Prompt 检查」能在重启后继续查看这些数据。原始请求是 provider-neutral 请求，供诊断使用；协议转换后的 HTTP 报文仍以请求日志为准。仅有远程图片 URL 的内容不会额外下载，远端失效仍可能影响显示。

检查点不设自动过期时间，直到明确重置会话或删除实例。24 小时未活动的会话可以卸载出内存，磁盘检查点仍保留。上下文条数、compact 和缓冲预算继续限制模型实际看到的内容；持久化不会无限扩展上下文窗口。检查点仅保留最新状态，不是每一轮对话的完整历史档案。

重启不会重新执行未完成的模型请求、工具或发送动作，也不会恢复执行队列。群聊尚未通过准入的暂存消息不会成为可信历史。重置和删除会写入新的版本或删除标记，旧的异步写入不能使上下文复活。

## 写入与数据库故障

每次变化先将完整检查点写入实例目录 `session-checkpoints/` 的临时文件，同步文件后原子替换。随后异步写入 SQL `session_states` 表，每个实例、每个会话保留一个递增版本。迁移使用 schema v18，旧程序不能通过修改版本号强行打开。

SQL 写入失败时保留最新待提交版本，每秒重试。恢复后按版本条件更新，较旧版本不能覆盖较新状态。本地镜像在提交成功后仍保留；启动合并 SQL 和本地快照，选择较新版本。同版本内容冲突时会显示异常，保留本地冲突副本（`.conflict`）供排查，正常情况下使用 SQL 版本；副本无法写入时保留可读取的本地版本。冲突副本不自动恢复。两处都损坏或磁盘写入失败时无法保证完整恢复，管理页会显示异常，不会将失败伪装成已持久化。

已启动实例在数据库连接故障期间继续使用当前会话和最后有效的模型路由；可选记忆读取、观察和提取失败不会暂停聊天。依赖数据库的记忆操作会失败，安全审查、权限检查、计费和安全清理仍遵守原有约束。可连接但内容无效的模型配置不会回退使用旧路由。

服务冷启动仍需读取实例配置和模型配置的数据库；本地会话镜像保存了数据，但不包含一套离线启动配置。数据库修复后可恢复镜像中的最新会话。磁盘本身损坏需要外部备份，副本与原件放在同一磁盘不能代替备份。

实例完整 ZIP 包含 `session_states.json`，也包含尚未提交 SQL 的本地版本及请求已有的内联媒体。恢复到新实例；旧 ZIP 没有此成员时保持兼容。检查点和请求可能包含聊天隐私及工具返回内容，应与实例数据、备份一起保护。

## 实例日志

每个实例默认使用 **128 MiB** 预算，在实例设置「日志与持久化」修改 `LOG_STORAGE_MIB`，保存后立即生效。允许 1～65536 MiB；清除配置后恢复默认值。无固定保留天数，预算内持续保留，超额从最旧的日志开始删除。停用实例、重启服务不会清空日志。

日志独立保存在实例目录 `logs/`，每条记录连同图片原子写入，不依赖业务数据库。预算按文件内容字节计算，包含 JSON 文本、图片编码与序号元数据，不按文件系统分配块或目录项计算。单条记录大于预算、磁盘满或无写入权限时会报告持久化失败，内存日志仍受原有预算限制。

日志序号跨重启延续；错误日志仍另带 UUIDv4，可在记录尚未被清理时跨重启定位。普通日志没有额外的错误 UUID。主动清理和超额淘汰不可通过普通重启找回。日志预算不包含会话检查点，清理日志不会清理会话上下文或最近请求快照。

Control Plane（General）日志仍属于进程内日志。实例完整 ZIP 保存会话与业务数据，不包含本地诊断日志；需要迁移诊断日志时同时保留实例的 `logs/` 目录。
