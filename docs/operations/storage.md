# 数据库与备份

当前应用使用 SQL 保存实例配置和持久化业务数据，支持 SQLite 与 PostgreSQL。模型供应商、密钥、模型目录和安全状态属于共享数据，实例路由、人格、记忆、群摘要与贴图元数据属于实例数据。贴图原始图片仍保存在本地数据目录。

## 选择数据库

默认 SQLite 文件为 `data/frostagent.db`。在「系统设置 → 数据库设置」选择 PostgreSQL，填写实际连接地址，再点击「保存并切换」。

```text
postgres://<用户>:<密码>@<主机>:5432/<数据库>?sslmode=<实际TLS模式>
```

连接串包含凭据，应按部署环境配置 TLS 并控制访问权限。目标连接或应用失败时保持当前数据库。

::: warning 切换不会迁移数据
切换后立即加载目标库已有配置和实例；空目标库会显示空实例列表。原数据库的数据不会自动复制过去，目标库也可能使用不同监听地址。切换后需重新选择实例，必要时从目标管理地址重新打开控制台。
:::

本地 SQLite 仍保存数据库选择，即使使用 PostgreSQL 也不能随意丢弃本地 `data/`。同一个 PostgreSQL 数据库只允许一个 FrostAgent 进程持有租约，不能用它搭建多个同时写入的服务副本。

## 应用层备份

在当前实例的「系统设置 → 备份与还原」下载存档：

| 导出                   | 内容                                                                              |
| ---------------------- | --------------------------------------------------------------------------------- |
| 全量 ZIP               | 设置、路由、引用的共享模型定义、MCP、示例对话、记忆、档案、归档、群摘要与贴图图片 |
| `setting.json`         | 实例非密钥设置、路由、MCP 与示例对话                                              |
| `memory.json`          | 私聊 / 群聊记忆、群档案与反思归档                                                 |
| `stickers.zip`         | 贴图元数据和原始图片                                                              |
| `group_summaries.json` | 群聊运行摘要                                                                      |
| 全局设置 JSON          | 全局配置，单独导出                                                                |
| 全局访问与审计 JSON    | 全局访问锁和安全审计，单独导出                                                    |

应用导出会置空密钥与凭据来源，只包含当前实例引用的共享供应商和模型。全量实例存档不包含全部全局数据、运行中的内存会话、所有日志或外部沙箱文件系统。

包含 #194 的版本还支持 [Embedding 向量索引](../usage/embedding)，应用导出和 ZIP 不携带这些派生向量。还原后用已保存的记忆和有效路由重建；SQLite 向量只存内存，PostgreSQL 向量依赖目标库预先启用的 pgvector。

## 还原与导入

- **全量还原**：从 ZIP 创建新实例，默认停用；检查供应商凭据、路由与适配器地址再启用。
- **设置导入**：替换当前实例的非密钥设置、路由、MCP 和示例对话；导入文件中的密钥忽略。
- **记忆合并**：按 ID 合并，同 ID 跳过，现有群档案优先；不同 ID 的重复语义需要人工查重。
- **全局设置导入**：保留当前密钥，自动应用导入配置。
- **访问与审计导入**：替换当前全局记录，操作前保留旧存档。

共享供应商定义匹配时复用已有凭据；定义冲突时新增供应商且置空密钥，不覆盖其他实例正在使用的定义。新实例 ID 与原实例不同，要重新配置上游和动作回传目标。

分项导出不意味着每一种文件都有独立上传入口；贴图与摘要随全量 ZIP 还原，设置和记忆另有对应导入入口。

## 数据库与目录备份

应用导出方便实例迁移；完整灾难恢复还需要数据库、图片目录、数据库选择以及外部 Secret 文件 / Windows 凭据的单独保护。

SQLite 使用 WAL 模式，运行时只复制主 `.db` 文件可能遗漏未合并写入。可在停服且数据库连接关闭后备份完整 `data/`，或使用数据库一致性备份工具。PostgreSQL 使用其数据库备份流程，并一并保存本地图片与选择记录。

当前没有自动导入旧 `.env` 或 `brain.json` 目录的升级流程，见[升级说明](./upgrading)。
