# 日志与故障排查

先确定故障发生在启动、实例、模型、工具还是投递层。选择正确实例后打开「日志查询」，按时间与类型检查 `SYSTEM`、`LLM_REQUEST`、`LLM_RESPONSE`、`TOOL` 等记录。

## 启动和构建

| 现象                        | 处理                                               |
| --------------------------- | -------------------------------------------------- |
| `gen/proto` 包不存在        | 生成 Go 协议代码；先安装 Buf 与本地插件            |
| 嵌入前端资源缺失            | 先构建 `@frostagent/web`，再编译 Go 服务           |
| Make 无法启动 Bash          | 准备 Bash，或使用 PowerShell 分步构建              |
| 端口被占用                  | 确认旧进程与实际监听地址；更改地址后重新打开控制台 |
| PostgreSQL 无法连接         | 检查连接串、TLS、账号权限、网络与目标库状态        |
| 提示另一进程使用 PostgreSQL | 关闭使用同一数据库的其他 FrostAgent 进程           |

## 已连接但 Bot 不回复

按以下顺序核对：

1. 当前实例是否启用，配置是否保存并自动应用成功，是否显示运行错误。
2. 主对话绑定是否发布，Endpoint / Model 是否启用，凭据是否有效。
3. 私聊是否能回复；群聊是否开启回复，并包含实际唤醒信号。
4. 上游是否转发此消息，AstrBot 是否仍开启自身 LLM。
5. 用户是否处于全局访问锁，aggressive 网关是否发生故障。
6. 模型是否调用 `stay_silent`、返回空结果或达到循环上限。
7. 回复动作是否收到成功回执。

群背景消息、概率未命中、模型主动选择静默、未授权管理员指令候选都可能没有普通回复，应通过对应日志判断。

## 模型和工具

| 现象               | 检查                                                  |
| ------------------ | ----------------------------------------------------- |
| 401 / 403          | 凭据来源、运行账号、上游权限                          |
| 404 / 请求路径错误 | Endpoint 基地址是否已包含所需 `/v1`，是否误填完整接口 |
| 模型不存在         | 上游实际模型名，不是界面显示名                        |
| 图片无法理解       | 视觉路由、模型真实图片能力、图片内容可达性            |
| 工具一直失败       | 参数 Schema、MCP 连接 / 工具开关、沙箱状态与工具结果  |
| 模型用错           | 实例默认绑定、当前群覆盖以及草稿发布状态              |

需要核对上下文时打开「会话与 Prompt」，再比对实际 `LLM_REQUEST`。命令和 stdout / stderr 会出现在工具日志，不能假设全部日志已脱敏。

## 网络、图片与备份

- WebSocket 404：检查实例 ID、路径和端口，旧 `/ws/astrbot` 地址不适用。
- 浏览器连接被拒：检查 Origin、HTTPS / WSS 和代理 Upgrade。
- AstrBot 贴图失败：检查 `http_base_url` 可达性和插件投递回执版本。
- 数据库切换后实例消失：确认目标库本身的数据；切换不会自动迁移。
- 还原后模型鉴权失败：存档置空密钥与凭据来源，重新配置后发布。
- 重启后近期聊天消失：内存会话不是持久化聊天记录，长期记忆与摘要另行保存。

## 提交问题报告

提供源码版本、操作系统、协议与插件版本、复现步骤、预期 / 实际结果，以及对应时间段的错误日志。使用合成身份替代真实 QQ、账号和邮箱，删除 API Key、Token、数据库密码及不必要的聊天内容。
