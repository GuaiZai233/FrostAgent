# 升级说明

本文档描述当前主分支的 SQL 运行方式。旧 README、历史白皮书或旧配置中的路径可能对应文件存储时代，升级前要保存原程序和完整数据副本。

## 当前与旧版的区别

| 旧用法                                | 当前方式                                                  |
| ------------------------------------- | --------------------------------------------------------- |
| 根 `.env` 和实例 `.env`               | SQL 设置，通过控制台修改                                  |
| 根级 `SYSTEM_PROMPT`                  | 实例人格设定；全局提示词不会回填实例                      |
| 实例 `model_router.json` 与私有供应商 | 共享供应商、密钥与模型目录，实例独立路由                  |
| `brain.json` 作为运行时主存储         | SQL 记忆，应用层 `memory.json` / ZIP 导出                 |
| 自定义适配器路径                      | 固定实例路径 `/instances/<ID>/ws/onebot` 或 `/ws/astrbot` |
| Angular 控制台说明                    | Vite + 原生 TypeScript 控制台                             |

## 文件存储时代的数据

当前 `cmd/app` 只加载所选 SQL 数据库，不会自动读取、导入或迁移旧实例目录、`.env`、`brain.json`、旧模型 JSON 与旧群记忆文件。留下旧文件不代表数据已进入新数据库。

如果来源版本能生成与当前应用格式兼容的存档，可通过「备份与还原」导入。只有旧原始文件时，先保留原副本，在旧程序中导出可用数据，再按当前导入格式评估转换；当前没有一键旧目录迁移命令，不能直接把 `brain.json` 重命名为 `memory.json`。

旧 `agent export/import/list/stats` 仍然针对 JSON 文件。它不连接 SQLite / PostgreSQL，不能用于证明当前实例数据库已完成导入或备份。

## 已使用 SQL 的版本升级

1. 导出重要实例和全局设置、安全数据，并保留数据库与图片的一致性备份。
2. 停止旧进程，记录工作目录和数据库选择。
3. 更新源码并用锁文件安装依赖，重新生成协议和构建程序。
4. 从原工作目录启动，数据库 Schema 按当前程序执行版本迁移。
5. 核对实例列表、共享供应商、路由、人格、记忆、图片和安全状态。
6. 同步升级 AstrBot 插件，再验证真实平台收发和外部集成。

数据库迁移不等于数据格式向后兼容。若需要回退程序版本，应从升级前备份恢复，而不是假设旧程序可以读取已升级的数据库。

SQL Schema 以 v7 为不可变基线，程序只按顺序执行缺失的 Migration。低于 v7 或高于当前程序所支持版本的数据库会保留原 Schema 和业务数据并拒绝加载；不会自动删表或重建旧库。每步结构变更、数据转换和版本推进在同一事务内提交，该步失败时回滚并停止启动；已经完成的前序步骤保持完成状态，修复后可重试。

当前 Schema 为 v14：v11 共享模型目录，v12 / v13 维护 Embedding 输入限额、摘要刷新标记及开发布局兼容，v14 增加 Skills。不要为了导入新功能修改已发布的迁移编号；旧实例全量 ZIP 没有 `skills.json` 仍能还原。

共享供应商迁移会重映射冲突 ID、名称与路由，旧表保留为迁移存档。无法安全处理的 Windows 凭据 Endpoint ID 冲突会拒绝升级，不猜测或覆盖系统凭据。具体开发约束见[SQL Schema Migration](../development/#sql-schema-migration)。

## 插件升级

新版引用回查、Bot 对话打断与贴图投递回执依赖相应 AstrBot 插件能力。后端和插件分别更新，并重新确认实例专属地址与 HTTP 根地址。

戳一戳通知转发需要插件 0.1.4 或更新版本，并在后端另行开启。示例对话的旧 `scene`、`relation` 字段已经移除，当前结构为 `id` / `user` / `preferred`。

## 容器部署升级

从带 Caddy gateway、Basic Auth 或本地 CA 的旧容器方案升级时，先备份数据库和卷，使用旧 Compose 文件停止旧服务（不加 `-v`），再按[Docker 指南](../guide/docker#配置、升级和验证边界)选择新拓扑。管理认证由 Cloudflare Access 承担，不能把旧账号配置当成当前认证。

保留相同 Compose 项目名以复用数据卷；旧证书卷不自动删除。现有 SQL 管理地址必须为数值回环 IP 且不同于适配器端口，否则容器拒绝启动。已有自定义管理端口继续有效，Tunnel 回源要同步；切到 host 方案前检查 SQL 中保存的适配器监听地址。

## JSON 群存储兼容与人工恢复

以下仅适用于直接使用 JSON `GroupManager` 的存储目录。当前正常运行实例使用 SQL，本步骤不会把旧 JSON 导入 SQL。

旧的 `groups/<SafeGroupKey>` 目录保留 QQ 兼容路径；此前的 JSON 群列表同样通过 QQ getter 读取它们。目录和文件均未记录可靠的平台归属，不能据此判断历史数据实际来自哪个平台。非 QQ 群使用 `groups/p_<平台 UTF-8 字节的小写十六进制>_<SafeGroupKey>`，不会自动接管旧目录。

如果通过外部记录确认某个旧目录完整属于一个非 QQ 群，可人工恢复：

1. 停止所有访问该 JSON 目录的进程，将整个 `groups` 备份到活动目录之外。
2. 确认平台与群 ID，检查原目录名确实为该群规范化 ID 的 `SafeGroupKey`。平台按 `CanonicalPlatform` 规范化；空值、`qq`、`onebot`、`aiocqhttp` 属于 QQ，无需改路径。
3. 为非 QQ 目录添加平台前缀。例如 Telegram 的 UTF-8 十六进制为 `74656c656772616d`，将整个 `groups/g_...` 移到 `groups/p_74656c656772616d_g_...`，保留目录内所有文件和内容。目标必须不存在；若已存在，停止操作，不覆盖或自动合并。
4. 重启后核对群列表的平台、群资料、成员称呼、记忆及主题目录，并保留备份。来源不能确认或已混写多个平台时，保留备份供人工核查，不把整份数据复制给多个平台。
