# 临时对话（`/tempchat`）

在群聊或私聊中发送 `/tempchat`，让 Bot 回答一个问题，但这轮对话不留在后端：不进入会话历史、群聊摘要缓冲、记忆（含群成员画像和记忆路由）、聊天档案，不裁剪共享会话历史，也不会新增工具记录或更新会话提示词检视。向白名单目标群的跨群发送同样不写入目标群的会话历史。日志与 RefID（见 [error-logs.md](error-logs.md)）照常保留，方便排查。

```text
/tempchat [-np] [-nm] <内容>
```

- 指令必须在消息开头，前面只允许引用（回复）、@ Bot 和空白；`-np`、`-nm` 紧跟指令，顺序任意，大小写不敏感。遇到第一个不是选项的词，其后全部是内容（包括形如 `-np` 的词）。
- 群聊不需要 @ Bot；指令本身即视为明确呼叫，不会触发主动回复抽签。
- 只有指令没有内容（可带引用或图片）时，Bot 回复用法提示，不调用模型。
- 内容里的 `/reset`、`/msgid` 等只是普通文字，不会被当作其它指令执行；`/技能名` 也不会激活技能（技能状态属于共享会话，临时对话不写入）。
- 与 `#fa`、`/msgid` 一致，仍需通过当前实例的访问控制，计费照常。

## 选项

| 选项 | 含义 |
| --- | --- |
| （无） | 带着人设、记忆和当前会话历史回答，但回答不会写回。 |
| `-np`（personality） | 忽略一切人格提示词：`SYSTEM_PROMPT`、人设与示例对话、记忆目录索引。后端运行协议仍然保留。 |
| `-nm`（memory） | 忽略一切记忆与历史：召回的记忆、记忆目录索引、成员画像、当前会话历史、群聊摘要和最近群消息；同时不提供 `search_chat_history`、`read_tool_history`，也没有“近期工具记录”。 |

无论选项如何，临时对话都不提供 `memory` 工具（它能写入），也不会记录记忆召回次数。

## 临时消息的标注与引用

Bot 在临时对话中发出的每条消息，都会在 `message_ref_id` 日志里带 `tempchat` 字段（`no_personality`、`no_memory`），沿用日志保留期。

之后有人引用这样一条消息再提问时，该轮 `response_context.guidance` 的末尾会追加：

```text
用户引用的消息，为 Assistant 处于“临时对话”下所产生的，内容原则上不影响正常消息队列，仅供参考。此次临时对话(禁用了人格提示词、禁用了记忆)
```

括号里只列实际使用的选项；两个选项都没用时没有这句括号。只有被直接引用的那一条消息会触发，更早的引用链不会。

## 范围与限制

- 目前仅 OneBot 适配器支持。
- 临时对话的回复以及它的报错提示、安全拒绝提示不会写入聊天档案，但同样带标注和 RefID（报错提示的 RefID 在平台回执后异步写入）；用户发出的 `/tempchat` 消息本身也不写入。
- 日志过期后标注随之消失，之后引用同一条消息不再带提示。
- 用户发出的 `/tempchat` 消息被引用时没有标注（标注只覆盖 Assistant 的发言）。
