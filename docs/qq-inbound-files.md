# QQ 接收文件与读取

原生 OneBot 接收到普通 `file` 消息段后，只登记当前会话的附件元数据，不会自动下载。
在模型处理该消息或同一发送者的后续问题时，`received_files` 列出当前可用的附件：
引用 `ref`、文件名、来源消息 ID、平台声明的大小和 `status=available`。

模型确实需要读取某个附件时，才调用 `import_received_file` 并传入该附件的 `ref`。
工具只把这一个文件下载并导入当前会话沙箱，返回沙箱路径、实际大小和
`status=ready`；失败时返回 `status=unavailable` 与原因，不把文件名占位符当作文件正文。
音频、视频等任意类型的附件都可以这样按需导入（例如用 ffmpeg 处理）。

模型随后通过 `execute_command` 读取路径。例如 DOCX 可使用 `python-docx`，或 Python
标准库 `zipfile` 和 XML 解析器。附件内容按用户数据处理；不会自动执行附件中的程序。
下载地址、平台文件凭据和传输 Base64 不进入模型上下文，`ref` 由会话、epoch、来源消息
和附件序号派生，不包含平台凭据。

## 授权与额度

- 工具调用时重新校验授权：同一 OneBot 连接、同一会话与 epoch、登记未超过一小时，
  且附件由当前发送者发送或其消息在本轮被引用。其他会话、其他发送者未被引用、
  会话重置后或已过期的 `ref` 均被拒绝，不会下载。
- 通过引用首次登记的附件归属被引用消息的真实发送者，而不是引用者；`get_msg` 未返回
  发送者时，该附件只能在引用它的轮次中访问。
- 每轮所有导入合计不超过 30 MiB；同一轮重复导入同一附件不重复计入额度。
- 沙箱未启用或健康检查失败时，工具返回明确错误，不下载文件。
- 主动回复（未唤醒）轮次不能调用该工具，也不会列出附件。

## 连续消息与引用

- 私聊先发文件、紧接着提问时，前一轮取消不会丢失附件描述；下一轮仍可列出并导入。
- 群内未 @ 机器人的普通文件通过入站安全检查后也会登记；同一发送者稍后 @ 提问
  即可列出，不依赖网关额外发送上传通知。登记本身不会触发对话或下载文件。
- 引用文件消息时，沿用已有 `get_msg` 会话校验和引用安全审查，被引用的附件会被
  优先列出，之后可按需导入。
- 群聊和私聊文件路径分别属于其来源会话；跨群发送白名单不会扩大读取范围。
- `group_upload` 和 `offline_file` 文件通知只登记附件，不主动触发回复；发送者后续
  在相同会话提问时可导入。通知没有消息 ID 时，不生成可供引用的虚假 ID。

附件描述仅缓存在当前 OneBot 连接内，最多 128 项、保留一小时；重连或会话重置后
重新发送或引用文件可重新取得附件。每轮最多列出最近的 8 个附件（当前消息和引用
消息中的附件优先）。导入成功的文件留在沙箱的 `/sandbox/received/` 中，受沙箱本身
的会话生命周期约束。复用前检查文件大小和 SHA-256；沙箱重建、文件删除或修改后会
重新导入。

## 下载和导入失败

优先使用网关提供的下载 URL；缺失或失效时，使用文件 ID 请求
`get_private_file_url` 或 `get_group_file_url`。只接受 QQ 文件下载域名：
`multimedia.nt.qq.com.cn`、`gchat.qpic.cn`、`c2cpicdw.qpic.cn`、`offline.qq.com`
及 `*.ftn.qq.com`，并校验重定向和解析后的网络地址。不读取网关或宿主机本地路径。
连接前校验全部 DNS 结果：拒绝内网、CGNAT（包括 `100.100.100.200`）、基准测试 /
fake-IP、文档、保留及协议专用网段。IPv4 映射地址按原始 IPv4 校验；IPv6 仅接受
`2000::/3` 中的普通公网地址，排除文档、Teredo 和 6to4 等特殊用途。任一 DNS 结果
不合规时整次连接失败；只向已校验的数字 IP 拨号，重定向后的新连接也使用相同策略。
地址策略的来源及维护说明见代码中的 IANA 注册表链接。

沙箱未启用、下载地址不支持、超时、文件为空、大小不符或超出额度时，工具会向模型
报告附件不可用。下载并不依赖沙箱联网；文件由 FrostAgent 后端下载，经现有沙箱协议分块
写入临时文件，校验完整内容后再原子发布。目录或目标为符号链接时拒绝导入。
传输最多并发执行 8 个分块请求，每块写入独立偏移，所有请求结束后才提交或清理。
取消、超时或失败后，使用独立的 5 秒清理预算删除本次未完成的临时文件。
