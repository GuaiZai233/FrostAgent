# QQ 接收文件与读取

原生 OneBot 接收到普通 `file` 消息段后，会登记当前会话的附件。在模型处理该消息或
同一发送者的后续问题时，后端下载文件并导入当前会话沙箱，向模型提供
`received_files` 中的文件名、来源消息 ID、大小、状态和沙箱路径。
仅 `status=ready` 表示导入成功；失败时提供原因，不把文件名占位符当作文件正文。

模型通过 `execute_command` 读取路径。例如 DOCX 可使用 `python-docx`，或 Python
标准库 `zipfile` 和 XML 解析器。附件内容按用户数据处理；不会自动执行附件中的程序。
下载地址、平台文件凭据和传输 Base64 不进入这段模型上下文。

## 连续消息与引用

- 私聊先发文件、紧接着提问时，前一轮取消不会丢失附件描述；下一轮会继续准备文件。
- 引用文件消息时，沿用已有 `get_msg` 会话校验和引用安全审查，随后导入被引用的附件。
- 群聊和私聊文件路径分别属于其来源会话；跨群发送白名单不会扩大读取范围。
- `group_upload` 和 `offline_file` 文件通知只登记附件，不主动触发回复；发送者后续
  在相同会话提问时可读取。通知没有消息 ID 时，不生成可供引用的虚假 ID。

附件描述仅缓存在当前 OneBot 连接内，最多 128 项、保留一小时；重连或会话重置后
重新发送或引用文件可重新取得附件。每轮最多准备最近的 8 个附件，合计不超过 30 MiB。
导入成功的文件留在沙箱的 `/sandbox/received/` 中，受沙箱本身的会话生命周期约束。
复用前检查文件大小和 SHA-256；沙箱重建、文件删除或修改后会重新导入。

## 下载和导入失败

优先使用网关提供的下载 URL；缺失或失效时，使用文件 ID 请求
`get_private_file_url` 或 `get_group_file_url`。只接受 QQ 文件下载域名：
`multimedia.nt.qq.com.cn`、`gchat.qpic.cn`、`c2cpicdw.qpic.cn`、`offline.qq.com`
及 `*.ftn.qq.com`，并校验重定向和解析后的网络地址。不读取网关或宿主机本地路径。

沙箱未启用、下载地址不支持、超时、文件为空、大小不符或超出额度时，会向模型报告
附件不可用。下载并不依赖沙箱联网；文件由 FrostAgent 后端下载，经现有沙箱协议分块
写入临时文件，校验完整内容后再原子发布。目录或目标为符号链接时拒绝导入。
