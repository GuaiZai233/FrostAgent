# 隔离沙箱

`execute_command` 将模型生成的命令交给外部沙箱执行。FrostAgent 通过 HTTP 调用沙箱网关，不在宿主机直接执行模型生成的 Shell 命令，也不会在沙箱失败时回退到宿主机。

## 启用流程

1. 单独部署兼容的沙箱网关与隔离 Worker。
2. 在全局 Bot 服务端设置填写网关地址、认证 Token 和会话基础命名空间。
3. 保存并确认控制面应用成功，再启用沙箱。
4. 在实例中调用简单命令，检查工具结果和沙箱服务日志。

| 设置                        | 默认 / 用途                             |
| --------------------------- | --------------------------------------- |
| `SANDBOX_ENABLED`           | 默认关闭，可运行时切换                  |
| `SANDBOX_BASE_URL`          | 默认 `http://127.0.0.1:3874`            |
| `SANDBOX_AUTH_TOKEN`        | 网关认证，启用时必填                    |
| `SANDBOX_SESSION_NAMESPACE` | 默认 `frostagent`，实例与会话进一步隔离 |

当前客户端支持 FA-Sandbox 的 `/api/v1/shell/exec`，在接口返回 404 时兼容回退至 code-interpreter 的 `/api/v1/execute`。选择哪种网关后，按它自己的部署文档准备容器或其他隔离环境。

## 会话生命周期

同一 FrostAgent 会话的多次调用可以保留沙箱文件；每次调用是独立 Shell 进程，不保证前一次的进程变量或 `cd` 状态持续存在。不同会话对应不同隔离空间，缺少会话 ID 时拒绝执行。

临时直接对话连接断开时会释放对应沙箱资源。网关被停用后，后端仍会尽力清理已建立的会话。

## 失败与日志

沙箱未启用时，工具仍存在，并明确提示管理员启用。网络离线、超时、认证失败或协议异常会返回错误；模型不能把错误描述成成功执行。

stdout / stderr 有大小限制，长输出会截断。工具日志保留命令和执行结果，分享日志前应检查是否含敏感业务信息。网关认证 Token 由控制面请求携带，不应作为命令参数传入 Worker。

Stdio MCP 服务器是管理员配置的进程，其权限模型与模型命令执行的沙箱不同；配置 MCP 不会自动把它放进此沙箱。
