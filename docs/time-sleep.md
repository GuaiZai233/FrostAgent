# 等待工具 time_sleep

模型可以调用 `time_sleep`，在当前执行中等待一段时间，例如等待用户把话说完。参数为正数秒数，支持小数：

```json
{"seconds": 10}
```

在概览的已注册工具能力中，可以启用、关闭或配置该工具。单次挂起超时默认为 **60 秒**；达到或超过超时上限的请求会先等待到上限，再返回 `Timeout` 工具错误。超时上限使用实例配置 `TIME_SLEEP_TIMEOUT_SECONDS`，留空恢复默认值，保存后下次工具调用生效。

正常完成或超时后，智能体继续当前执行，递增一次思考计数并消耗原有迭代预算。不会因为等待重新计算一个 Bot 对话轮次，也不会重置计费、技能、工具记录或沙箱会话。

群聊恢复思考前会重新读取当前会话的压缩摘要和最近追加消息，替换当前请求中的临时群聊背景。最近消息仍受原有条数、字符数、安全审查和 compact 白名单限制；尚未确认的 staged 消息不会进入背景。用户原文、引用和图片保留，刷新后的临时背景不会写入共享历史或继承给下一次执行。

同一发送者的新触发消息仍会立即打断当前执行，包括正在等待的 `time_sleep`，随后按现有机制携带已有执行记录继续处理并重置迭代预算。其他发送者继续独立处理；重置会话、停止实例或关闭关联会话也会取消等待。

工具批次仍按顺序执行。`time_sleep` 不会将其他同步工具转换为后台任务。
