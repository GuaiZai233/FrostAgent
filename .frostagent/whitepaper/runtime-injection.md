# 运行时消息注入

## 队列与触发

OneBot 与 AstrBot 的显式对话按实例、平台、会话、发送者维护独立内存队列。同群 A 与 B 可并发；A 的新输入只中断 A。私聊新消息、群聊真实 @、Bot 名称或别名触发注入。现有 poke 与 AstrBot 通用唤醒（例如引用 Bot）继续触发普通对话，但不新增为硬中断信号。安全网关、路由禁用、Bot-loop 限额仍在入队前执行。

新输入在 WebSocket 入站顺序上撤销旧轮次权限并请求取消。交接期间到达的多条输入按序保留，已被更新输入覆盖的待执行轮次只准备上下文，不发起模型请求；最新轮次将它们一起交给模型。新轮次开始后再次到达输入，则再次中断。

主动回复使用独立的群级替换队列，与个人队列互不打断。新命中替换旧主动回复，不继承旧工具轨迹、技能状态或已写记忆标记。概率、白名单、静默规则及现有工具权限保持不变：允许 `stay_silent`、`memory`、`send_sticker` 和显式实现主动回复许可接口的扩展工具。

## 上下文与资源边界

- 安全审查后的用户输入和已发送的 Bot 回复进入共享会话历史，其他发送者可在其新请求中看到；群记忆继续共享。
- 工具调用/结果、未发送的模型回答和技能参数属于发送者执行队列，不写入公共历史。中断链保留已完成的轨迹；任务结束释放临时轨迹，沿用既有普通历史规则。技能保持同人会话生命周期，重置会话清除。
- 注入时重建公共背景、动态系统提示和记忆；旧请求的瞬时群背景不重复追加。工具轮次不会每轮刷新公共背景；Skills 仍按现有规则每轮检查启用/版本。
- 沙箱仍按原 `SessionID` 分配，全群共享文件系统。技能状态隔离不是文件隔离，也不改变工具权限。
- 交接期间合并的手动技能调用保留其调用意图；最新输入按顺序激活。管理员 Prompt Inspector 仍展示实际发送的动态 Skills 提示，但不会将它写入公开历史。
- 群消息 compact / 长期记忆提取仍有 staged guard 与安全屏障。公共可见性不等于可立即用于长期提取。
- 不增加持久化格式、迁移或自动压缩。实例重启不会恢复在途队列。

## 取消、工具与输出

旧执行失去继续发起工具和发送回复的权限。模型/工具请求尽力取消；不配合取消的调用可继续在后台结束，其迟到内容不进入续跑上下文。已执行的远端副作用不回滚，也不保证远端进程立即停止。

部分工具批次在交接时补齐 tool-call/result 配对：完成的保留已审查结果；已启动但中断的标记“结果未知，先核实状态，禁止自动重复”；尚未启动的标记“未执行”。不自动重放整个批次。已确认发出的中间消息保留为公共回复。

传输在写入前检查旧轮次权限；已准入的网络写属于在途副作用，不能撤回。取消不等待写锁、socket 或 ACK，后继可继续思考；共用连接上的实际发送仍按传输写锁串行，写入使用 10 秒截止时间。已确认的发送独立记录为公共事实；未确认的 OneBot 发送仍标为结果未知。会话重置后不补回旧历史。

每次注入恢复完整配置的迭代上限；轨迹和消费累计不重置。128000-token 上下文硬上限与单工具输出上限继续适用。

AstrBot 对被中断旧消息发送 `noop` 且 `suppress_llm=true`，结束插件 waiter，避免触发下游原生 LLM。OneBot 继续以平台 ACK 判定交付；AstrBot 普通消息仍仅确认 socket 写入，贴纸沿用专用回执。

## 计费

每次模型调用由唯一的链内递增调用号标识，不复用重置后的迭代计数。调用工作单元独占 Reserve 的 Commit/Release：成功且有有效 usage 的旧响应即使被丢弃仍收费；真正失败或取消则释放预扣款，取消使用 `request_cancelled` 原因。

新输入无需等待旧模型调用返回即可开始。最终费用回执由当前任务链唯一有效的轮次负责，等待链内在途调用结算后聚合，并刷新余额以避免提交/退款响应乱序；旧轮次不独立发送回答或回执。后继输入即使因超长或视觉余额校验而提前退出，仍接管旧链费用，必要时单独发送回执。若提供方忽略取消且迟迟不返回，最终回执也需要等待其结束。结算状态由互斥锁保护；余额刷新失败记录告警并保留最近一次已知余额。

## Harness 调研依据

[Claude Code 的输入队列](https://code.claude.com/docs/en/interactive-mode#when-claude-code-sends-what-you-queued)区分排队输入与显式打断；普通排队通常在工具批次边界消费。[Pi 的 steering / follow-up](https://github.com/earendil-works/pi/blob/136b87e8a7f5a3e5186de0289523ba327dc592fc/packages/agent/README.md#steering-and-follow-up)也将 steer、followUp 与 abort 分开。本功能采用已确认的“硬中断后携带轨迹续跑”，不是简单复制工具批次结束后追加队列的语义。
