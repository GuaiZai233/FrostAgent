# AstrBot 与 FrostAgent 唤醒边界

维护者在 issue #112 中选择独立唤醒：AstrBot 的命令前缀和唤醒词只影响 AstrBot，不自动唤醒 FrostAgent。插件不继承 AstrBot 的 `is_wake` 或 `is_at_or_wake_command`，只从实际消息组件及原始 OneBot @段识别 @机器人，从引用组件识别引用机器人。

FrostAgent 后端继续处理实例名称与别名唤醒、群聊回复开关、私聊和独立配置的主动回复概率。插件的群消息全量转发开关控制后端能看到哪些消息，不把转发等同于唤醒。关闭全量转发后，后端无法从被插件过滤的普通文本中识别名称或别名。

Bot 连续对话防循环由后端按会话为每个标记 Bot 独立累计额度。其他 Bot 发言、普通群聊消息及主动回复都不恢复额度；仅未标记用户有效地明确唤醒（@、后端名称/别名或已启用的戳一戳）才恢复当前会话的 Bot 额度。插件仅因引用机器人设置的 `is_wake` 仍可唤醒对话，但不会单独恢复额度。未通过安全、路由或戳一戳冷却准入的静默拒绝不会恢复额度。

插件现有的 `bot_loop_interrupted` 字段继续兼容旧后端；新后端忽略该标记，避免过滤消息、插件重启或切换发送者重置额度。无需同步升级插件，也不会额外上报过滤消息的内容、发送者或会话信息。关闭全量群消息转发时，后端仍无法从被过滤的普通文本中识别名称或别名。

插件单元测试覆盖 AstrBot 前缀标记不会唤醒或绕过转发过滤、真实 @、引用机器人、引用其他用户及私聊转发。真实 AstrBot 命令执行与不同平台引用组件形态仍需平台集成验证。
