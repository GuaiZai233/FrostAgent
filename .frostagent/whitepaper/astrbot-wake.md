# AstrBot 与 FrostAgent 唤醒边界

维护者在 issue #112 中选择独立唤醒：AstrBot 的命令前缀和唤醒词只影响 AstrBot，不自动唤醒 FrostAgent。插件不继承 AstrBot 的 `is_wake` 或 `is_at_or_wake_command`，只从实际消息组件及原始 OneBot @段识别 @机器人，从引用组件识别引用机器人。

FrostAgent 后端继续处理实例名称与别名唤醒、群聊回复开关、私聊和独立配置的主动回复概率。插件的群消息全量转发开关控制后端能看到哪些消息，不把转发等同于唤醒。关闭全量转发后，后端无法从被插件过滤的普通文本中识别名称或别名。

Bot 连续对话防循环由后端按会话为每个标记 Bot 独立累计额度。其他 Bot 发言、普通群聊消息及主动回复都不恢复额度；仅未标记用户有效地明确唤醒（@、后端名称/别名或已启用的戳一戳）才恢复当前会话的 Bot 额度。插件仅因引用机器人设置的 `is_wake` 仍可唤醒对话，但不会单独恢复额度。未通过安全、路由或戳一戳冷却准入的静默拒绝不会恢复额度。

插件现有的 `bot_loop_interrupted` 字段继续兼容旧后端；新后端忽略该标记，避免过滤消息、插件重启或切换发送者重置额度。无需同步升级插件，也不会额外上报过滤消息的内容、发送者或会话信息。关闭全量群消息转发时，后端仍无法从被过滤的普通文本中识别名称或别名。

## 运行信息诊断例外

从插件 0.1.5 起，当前群消息顶层文本去除首尾空白后精确等于 `#fa` 时，作为 FrostAgent 保留诊断指令转发，不要求 @或管理员身份，也不受 `forward_all_group_messages=false` 过滤。可以带真实 @Bot 或引用标记；非 Bot 提及、媒体、未知组件及其他文本均不识别为诊断。识别只读取当前 Plain/text 组件；若同时存在标准化组件与原始 OneBot 消息段，两者必须一致，绝不从 `get_message_str()` 等字符串回退、引用链或历史正文中推断命令。

插件为所有普通消息显式传递布尔 `metadata.runtime_info_command`；只有已证明为当前命令的消息才为 `true`。该诊断载荷的 `content` 固定为 `#fa`，`attachments` 为空，不包含 `reply_message_id` 或 `quote_lookup_supported`，也不回传引用查询历史。诊断例外仅上报命令本身和必要的当前发送者、群组等事件标识，不扩大其他被过滤群消息的上报范围。

后端仅接受上述标记为 `true`、正文精确匹配且无附件的群消息，因此上线该功能需同步升级插件。FrostAgent 实例“输出FrostAgent默认运行信息”默认开启；诊断绕过普通群回复开关及模型路由，仍遵守用户封禁和实例停用，并且不产生模型请求。插件在任何等待或传输前抑制 AstrBot 默认 LLM；后端关闭功能/封禁、连接失败、发送异常、配置错误和响应超时均不回落到本地默认模型。私聊保持原有对话路径。

插件单元测试覆盖 AstrBot 前缀标记不会唤醒或绕过转发过滤、真实 @、引用机器人、引用其他用户及私聊转发；另覆盖诊断精确匹配、引用/媒体隔离、普通消息过滤和失败路径的默认 LLM 抑制。真实 AstrBot 命令执行与不同平台引用组件形态仍需平台集成验证。
