# Computer use：专用 Windows VM 与持久工作区

## 状态与交付边界

本文件记录已确认的产品规格，并单独标明已实现部分，不能将设计目标当作现有功能。

第一阶段新增 `internal/computeruse/bridge`：版本化操作协议、持久去重账本、
独立审计、带鉴权的 HTTPS handler、同操作 ID 重试/查询客户端，以及模拟执行器测试。
**目前没有生产 bridge 可执行程序、聊天工具注册、项目 API、工作台页面或 Windows 桌面执行器。**
这些代码不会自动给现有 Bot、沙箱或管理页面增加操作宿主机的权限。

后续阶段：

1. Windows 桥运行入口及执行器、项目注册/独立 worktree、固定工具链环境。
2. FrostAgent 持久任务编排、主人授权与撤销、独立工作上下文、预算、桌面独占与接管。
3. 真实管理工作台、备份元数据、VM 部署/登录恢复流程和真实 Windows VM 验收。

阶段边界用于交付与验证，不删减下述最终规格。只有全部接入并完成适当验证后，才可称为
可用的 computer use 功能。

## 架构与授权

可信主人私聊 / 管理工作台 → FrostAgent 模型循环与任务编排 → 私网桥 → 专用 Windows VM。

- VM 由操作者提供；FrostAgent 不创建或管理 hypervisor。每个 Bot 对应一台专用 VM。
- FrostAgent 主动连接桥；桥只是执行器，不再运行一套独立 AI Agent。
- V1 限定 LAN / VPN / 私网，不能因为网络可达就省略桥认证，也不提供直接公网部署承诺。
- 主人为实例 `ADMIN_QQ_IDS` 中的管理员；通过已有管理认证边界进入的操作者也拥有 VM 权限。
- 仅可信 QQ 私聊和真实管理工作台可创建高权限任务。群聊、主动回复、模拟聊天不可获得此能力。
  现有可编辑发送者身份的 Web mock chat 不是管理工作台，不可作为授权依据。
- 主人校验必须使用可信入口身份，在任务准入和后续操作时检查；不能将模型参数中的用户 ID
  或仅经过格式规范化的 Principal 当作已认证身份。
- 高权限工作会话独立，不自动携带群聊历史、群记忆、引用的第三方消息或普通聊天上下文。
- 这是整机权限委托，不是逐命令审批；可安装工具、管理版本及使用 VM 上配置的 Git 凭据。
  worktree 不是安全沙箱，各项目仍共享机器权限。
- 登录与 Git 凭据留在 VM 配置；不刻意向模型提供凭据。不能声称 Windows 管理员无法读取
  自动登录所需的秘密。

## 桌面、接管与恢复

- Bot 操作专用 VM 的交互式桌面，与 FrostAgent 宿主当前前台屏幕无关。
- V1 不承诺同一 Windows 会话里人类与 Bot 同时操作彼此隐藏的桌面。
- 最终部署流程包含自动登录、桥自启动及重启后的桌面恢复。不能把 Session 0 服务直接当作
  已登录用户的桌面执行器。
- 接管流程必须先暂停并确认自动 GUI 输入停止，再交给人类；恢复操作必须显式请求。
- **FrostAgent 重启不自动续跑未完成任务。** 恢复/核对状态后等待主人继续。桌面自动恢复不等于
  Agent 任务自动恢复。

## 项目、Git、worktree

- 配置的项目根目录下，每个主仓库文件夹是项目，要求有 `.git` **目录**。
- Coder 必须在独立 worktree 工作；其 `.git` **文件**是合法 Git 布局。
  前端可以将 worktree 组织为项目下的子工作区，不必当作顶层项目。
- worktree 从配置的基准分支/提交建立，不隐式复制主工作区的脏文件或未提交修改。
- 项目可配置 remote，保留 pull / push 能力。默认交付保留本地结果，不擅自 commit/push；
  任务指令或仓库 `AGENTS.md` 要求提交/推送时应遵循，不能一概禁止 push。
- 完成的 worktree 保留到显式清理；归档默认只隐藏记录，不删除文件。
- 删除 Bot 或项目注册不级联删除 VM 代码、worktree 或工具链；远端删除是单独的显式操作。

## 并发与工具链

- 终端任务可在各自 worktree 并行。
- GUI 独占租约覆盖有意义的连续操作，不在每次点击之间释放。
- 全局工具链/系统环境修改进入维护阶段，协调受影响任务，不能依赖 worktree 隔离解决。
- 工具链版本持久共存；任务固定实际可执行文件路径和环境。
  修改项目默认版本只影响未来任务，不悄悄改变正在运行的任务。
- V1 用 shell 和项目配置管理工具链，不要求专门的版本管理 UI/目录。

## 操作协议与持久语义（第一阶段已实现）

`bridge.Request` 包含协议版本、operation/instance/task/actor ID、任务 generation、
操作类型、操作超时及 JSON 参数。桥绑定一个实例；对该实例的桥令牌是整机权限凭据。
上游授权与撤销尚未接入，不能直接将此接口开放给聊天用户。

`PUT /v1/operations/{operation_id}` 提交或读取同 ID 的现有操作；
`GET /v1/operations/{operation_id}` 查询现有事实。默认请求最大 256 KiB，响应最大 16 KiB。
不支持旧版本、未知请求字段、路径/正文 ID 不一致或尾随 JSON。协议只接受 HTTPS；
令牌要求 base64url 字符集、32～256 字符，部署时必须使用足够熵的随机令牌。
客户端默认验证 TLS、不使用环境代理、不跟随重定向；私有 CA 通过可信传输配置提供。
服务 handler 不是部署服务器，后续运行入口仍须配置私网监听、连接/请求超时及操作账号 ACL。

操作身份签名覆盖整个请求，包括超时、actor 和 task generation。JSON 空白被压缩，
数值不经浮点转换；对象键的次序仍是请求身份的一部分。客户端复制并固定序列化请求，
重试复用原 ID/参数。相同 ID 不同参数返回冲突；同 ID 的并发或重复提交只读取已有记录。

| 状态 | 含义与恢复 |
| --- | --- |
| `accepted` | 已持久接受，尚未允许执行器运行；重启后成为 `failed / interrupted_before_execution` |
| `running` | 已持久记录派发，执行器可能已产生副作用；重启后成为 `unknown / bridge_restart` |
| `succeeded` | 执行器明确报告完成且已保存 |
| `failed` | 明确失败；不表示部分副作用不存在，不自动创建新操作重放 |
| `unknown` | 执行效果不能确定；查询/重试同 ID 仍返回该事实，不重新调用执行器 |

桥先持久写 accepted，写审计，再持久写 running 并完成派发审计，然后调用执行器。
HTTP 请求结束或断线不会取消已接受操作；执行器使用请求中固定的独立超时。
超时/取消信号不是进程终止证据：未返回的执行器仍占并发额度、保持 running。
明确的完成事实即使晚于超时到达，也应记录；上层编排仍须检查任务当前 generation/暂停状态，
不能让旧事实推动新任务自动继续。

执行器报错、panic 或返回不合法结果时保守记录 unknown，不持久化任意错误字符串。
只有固定元数据状态/代码和可选退出码进入结果记录。第一阶段**不传输或缓存命令输出、
源文件或截图**；后续添加内容传输时必须显式设计短期生命周期，不能塞进元数据字段。

客户端连接/通信失败按 250ms 起步、最多 10s 的指数退避重试，默认连续失败 5 次返回
“执行结果未知”；可配置。得到 accepted/running 后查询并等待；取消等待不等于取消执行。
查询中发现已接受操作丢失时停止，不再重新提交。显式失败/unknown 不盲目重放。
回复的 operation/task/instance/actor/generation/参数签名必须全部匹配。

每台桥的 `StateDir/operations.db` 是独立 SQLite v1 账本，**不修改 FrostAgent 主库 v14**。
采用 WAL 与 FULL 同步；操作账本不按审计保留期清理。OS 文件租约在 Windows/Linux 上防止
两个桥同时拥有同一账本；关闭超时不提前释放租约，必须等执行器全部返回。
账本与实例永久绑定，版本不兼容、记录损坏、读写故障时拒绝新工作。

此协议不承诺任意外部副作用的 exactly-once。断电、进程崩溃、损坏/回滚/丢失账本、
仍在后台运行的子进程，都需要核对实际状态。不得删除或回滚账本后自动重放旧任务。

## 预算、审计与隐私

- 最终任务编排支持可配置的时间、模型/工具轮数和并发预算；耗尽后暂停新的 Agent 操作，
  保留代码。不能把暂停调度描述为已有进程已停止。
- 第一阶段桥实现并发限额（1～64）和每个操作的独立超时（1ms～24h）；模型/任务总预算尚未实现。
- 审计使用独立 `AuditDir`，与 StateDir 不能相同或互相嵌套，也不写入普通 Bot/模型日志。
- 默认保留 **7 个 UTC 日历日**（当天及此前六天），按日生成 JSONL，保留天数可配置。
  只清理匹配本模块命名的过期常规文件，不删除子目录、symlink 或操作账本；轮转在写入时执行。
- 审计只包含时间、actor/instance/task/operation、generation、类型、状态和固定结果代码/退出码。
  不保存参数、源码、原始终端输出、截图、凭据或任意执行器错误文本。
- 新日志先写入并同步临时文件，再以不覆盖既有目标的方式发布；Unix 同步父目录，
  Windows 使用 write-through move，后续追加均同步文件。同步或发布失败都阻止派发。
  进程崩溃可能留下仅含元数据的 `.audit-create-YYYY-MM-DD-数字` 临时文件，按同样日期范围
  清理过期常规文件，其他未知名称不删除；不会让临时元数据绕过七天保留期。
- 审计落盘/同步失败后，本服务拒绝新的执行，等待操作者修复并显式重开服务；不能自动续跑任务。
  已运行操作的完成事实仍写入独立账本；完成审计失败也不会抹掉真实完成事实。
- 现阶段包不调用普通 LLM/工具日志。后续注册工具和模型循环时，必须阻止其参数/结果被常规
  日志再次记录；仅给桥增加隐私日志不能自动解决上游日志泄露。
- 最终功能可能按需要向配置的模型供应商发送代码/截图，包括云端供应商；须披露实际数据流。
  “私网桥”不代表内容始终留在 VM。

## 备份与验收

FrostAgent 的最终备份覆盖项目注册和任务元数据；VM、代码仓库、工具链磁盘备份由操作者负责。
当前阶段没有改变现有实例 ZIP 备份，也不声称它已包含 computer-use 数据。

第一阶段自动化验证覆盖同 ID 并发去重、参数冲突、实例绑定、OS 租约、实际子进程在模拟
副作用后崩溃、恢复不重放、响应丢失、旧 generation/错误参数响应拒绝、鉴权/TLS、审计故障、
日志内容边界及七天轮转。所有执行器都是测试替身，不执行桌面或用户命令。

真实 Windows VM 尚需覆盖：主人授权及撤销、独立会话、接管、开机/桌面恢复、并行 worktree、
固定工具链、GUI 独占、后台进程状态、断线/崩溃/未知结果、FrostAgent 重启不续跑和真实审计
权限故障。未提供专用测试 VM 时不得在开发者当前电脑上配置自动登录、安装桥服务或重启机器。

实现相关官方文档：[Windows MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)
说明 write-through move 的返回条件；[SQLite synchronous](https://www.sqlite.org/pragma.html#pragma_synchronous)
说明 WAL/FULL 的同步行为。文件系统/磁盘实际断电可靠性仍需要目标 VM 验证，不以单元测试代替。
