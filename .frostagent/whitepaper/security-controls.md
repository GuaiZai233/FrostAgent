## 全局安全控制体系

FrostAgent 将安全控制收束在共享的 `security.Controller`，而不是把权限判断分散到各个工具、平台适配器或实例运行时。本体系为 FrostAgent 所有平台适配器（OneBot、AstrBot 以及未来的 Telegram 等）提供统一的 Global Access Control 与 Watchdog 安全基础设施。

- **主体身份规范化与 Transport 解耦**：可信身份始终由平台适配器统一归一化生成，主键为 `(canonical_platform, user_id)`。Adapter/Transport 协议名称（如 `onebot`、`aiocqhttp`、`cqhttp`）明确与用户平台身份解耦，统一映射为标准平台标识（如 `qq`），确保同一真实用户在不同协议传输接入下共享同一身份标识与安全审计边界。模型输入、工具参数与模型文本均不可声明或伪造身份。
- **全局访问状态、存储错误冒泡与跨实例一致性（Atomic Access State & Error Propagation）**：`AccessStore` 将 `ACTIVE` / `LOCKED` 状态持久化到全局根数据目录（`BRAIN_PATH`），并使用跨进程文件锁和操作系统原子替换写入协调并发（Windows 平台采用带 `MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH` 的 `MoveFileExW`，POSIX 平台采用临时文件替换与父目录 `fsync`），杜绝因删除后重命名失败引发的 fail-open 风险。多实例共享全局唯一 Controller，任何实例或适配器发生的手动管理锁定操作立即对全量实例和全部适配器生效。`AccessStore` 的所有核心方法（`IsLocked`、`Lock`、`Unlock` 以及 `LastBlockedHash`）均完整显式返回并向上冒泡底层 I/O、损坏或原子更新错误，杜绝静默吞错退化为失真状态。
- **纯 LLM 安全网关架构与 Option A 严格 Fail-Closed（Pure LLM Gateway Architecture & Option A Fail-Closed）**：
  - 彻底移除了原先硬编码在 `watchdog.go` 内的静态正则表达式列表（`dangerousPatterns`），并遵照 Maintainer 架构裁定**将本地基于规则/正则的语义内容分类器（`CalibratedClassifier`）和通用回退分类器（`HybridClassifier`）从整个代码库中完全物理删除**。语义安全风险分类职责完全收束至基于 `core.LLMProvider` 驱动的 LLM 安全网关。系统保留完整的确定性安全底座（输入规范化、来源溯源、内容哈希、规避检测记账、大小限制、AccessStore 状态与审计脱敏日志），但语义违规判定由且仅由 LLM 网关完成。
  - **`LLMClassifier`（纯 LLM 语义安全网关）**：基于 `core.LLMProvider` 驱动的高鲁棒性安全网关，采用 `<content>...</content>` 隔离定界符与 `EscapeXML` 实体转义（对 `&`、`<`、`>`、`"`、`'` 进行全量字符实体编码）防御定界符注入逃逸，彻底杜绝攻击者闭合 `</content>` 并注入伪造系统指令的攻击面；通过严格结构化 JSON 输出对输入文本进行语义级越狱、破坏性命令与数据窃取分析，具备天然的跨语言防御能力。
  - **未配置/故障严格 Option A Fail-Closed**：当系统未配置 LLM 提供者（`provider == nil` 或 `classifier == nil`）或实例未装配网关时，系统坚决拒绝回退到任何本地弱规则，而是直接执行 Option A 严格 Fail-Closed 阻断（`WatchdogBlock`，0 strike，不封禁）。同样，当 LLM 出现超时、上游断连、网络报错或返回畸形/非结构化 JSON 时，一律执行严格 Fail-Closed 阻断，杜绝无网关或网关异常时的安全降级放行。
  - **确定性策略底座与语义网关评测彻底解耦**：单元测试中对确定性策略底座流水线（输入归一化、来源溯源打标、编码规避检测记账、跨实例并发同步与管理锁状态机）的验证完全采用仅存在于 `_test.go` 文件中的轻量级脚本化测试桩（Scripted Test Doubles），彻底不在生产代码中残留任何本地语义分类器代码。
  - **生产环境运行链路装配与多实例安全隔离（Production Path Wiring & Multi-Instance Gateway Scoping）**：在实例运行时初始化（`internal/instance/runtime.go` `buildRuntime`）中，控制器通过 `securityController.SetInstanceProvider(instanceID, routerManager.Provider(...), "model-router-security-gateway")` 为每个活跃实例建立严格隔离的专属 `*LLMClassifier`；当实例停用或删除时（`m.Enable(id, false)` / `m.Delete` / `m.stop`），自动通过 `securityController.RemoveInstanceProvider(instanceID)` 回收该实例的专属网关。停用或未配置专属网关的实例在 Ingress 评估时直接 Fail-Closed（`BLOCK`，0 strike，不封禁）。`Watchdog` 内部采用读写锁（`sync.RWMutex`）全量同步分类器读写操作，彻底杜绝实例热重载/重配置与并发 Ingress 审查之间的 Go interface 数据竞争（`-race` 安全）。在保持分类器按实例完全隔离的同时，维持全局唯一的 `AccessStore` 与 `AuditStore`，确保全局锁定状态跨实例原子同步生效。
  - **严格结构化输出与必填字段强校验（Strict Required-Field Structural Validation）**：LLM 返回的 JSON 载荷解析采用指针字段（`*string`）严格区分显式赋值与缺省零值，在枚举规范化前强制验证必填字段（`category`、`risk_level`）非空且必须存在，并严密校验双向分类不变量（`category == none <=> risk_level == none`）。彻底移除了已废除的 `confidence`、`intent`、`platform_policy` 字段以及空字符串向有效枚举（如 `none`）的隐式映射；空对象 `{}`、部分缺失字段（如缺少 `category` 或 `risk_level`）一律被拒绝并视作分类器失败，触发严格 Fail-Closed 阻断（0 strike，不封禁），杜绝恶意截断伪装放行。分类器返回的 `reason` 字段严格遵守诊断隔离不变量，仅作为内部排障与审计元数据使用，绝不参与策略路由分支，绝不直接拼接到用户可见错误或下游上下文中。
  - **分类器与存储故障隔离与无过错零惩罚不变量（Zero-Penalty Fault Isolation & Fail-Closed Invariants）**：
    - **分类器异常隔离**：当分类器由于模型超时、网络断开或输出解析失败向 `Watchdog` 返回错误时，`Watchdog` 无条件执行严格阻断（`WatchdogBlock`，`IsFailure: true`，`reason = "classifier evaluation error; fail-closed block"`）。同时，系统严格将分类器故障与用户惩戒隔离，分类审查完全不累计 Strike 计数，永不触发自动封禁（Lock），兼顾系统安全底线与用户体验。
    - **存储持久化与状态读取故障严格 Fail-Closed**：在安全门禁判定中，若底层存储在读取锁定状态、验证历史阻断哈希（`LastBlockedHash`）时遭遇持久化故障（例如磁盘已满、文件损坏、原子替换失败或并发锁冲突），或未配置 `AccessStore`，`Watchdog` 坚决拒绝静默退化为普通策略阻断（`IsFailure: false`），而是严格执行 Fail-Closed 基础设施异常阻断（`WatchdogBlock`，`IsFailure: true`），同时严格保证零惩戒（0 strike，不封禁），保留全局唯一的 `EvaluationID` 追踪并在系统日志记录 `Error` 级别告警（`安全控制存储状态异常 (Fail-Closed)`），并在用户侧明确提示审查服务异常（`RejectFailureMsg`）。绝不将存储不可用静默吞掉伪装成无历史记录。
  - **入口单次分类调用优化与排版归一化解耦（Ingress Single-Call Path Optimization & Typographic Decoupling）**：在 `Watchdog.EvaluateWithContext` 评估直接输入时，系统解耦了**安全规避转换（`EvasionModified`）**与**无害排版规整（`TypographicModified`）**。未经修改的原始输入以及仅包含常规全角中文标点（如 `，` `U+FF0C`、`？` `U+FF1F`、`！` `U+FF01`、`：` `U+FF1A`、`；` `U+FF1B`、`（` `）`、`～` 等）或全角空格（`U+3000`）的良性输入，不会被标记为安全规避转换（`evasionModified == false`），仅发起一次分类器调用并复用结果，将模型网关的耗时与 Token 成本降低 50%；唯有当输入包含真正的安全规避混淆手段（零宽字符、双向格式化字符、数学花体、全角字母数字 `0xFF10..0xFF19` / `0xFF21..0xFF3A` / `0xFF41..0xFF5A`、西里尔同形字替换、百分号编码还原、Base64 解密）时，才置 `evasionModified = true` 并触发第二次针对原始文本的分类审查，以精准识别编码规避行为并在审计事件中记录（`Event.Encoded = isEvasion`）。若第二次原始文本分类遇到任何超时、断连或格式错误，同样严格执行 Option A Fail-Closed 阻断并隔离惩戒（0 strike、不封禁），彻底封堵间歇性网络/模型状态抖动可能造成的降级放行漏洞。
- **信息边界降级流水线与受控风险信号体系（Information-Boundary Degradation Pipeline & Controlled Risk Signals）**：
  安全审查网关的核心职责是控制未经审查的原始内容向系统各安全边界（主 LLM、会话历史、精简上下文缓存等）的流转，而非代替管理员推断用户主观意图或施加二元惩戒。系统输出标准 `ClassificationResult`：
  - **单一策略决定依据（Single Policy Determinant）**：`risk_level`（`none`、`medium`、`high`、`critical`）是决定内容如何跨越安全边界流转的唯一字段。彻底废除 `confidence`（浮点数置信分）、`intent`（`IntentBenign`、`IntentAmbiguous`、`IntentMalicious`）及泛化的 `platform_policy`，不引入任何替代性的数值打分或经验阈值。
  - **规范化受控分类枚举（Controlled Risk Categories）**：严格定义 10 个受控枚举值：无风险（`none`）、提示词注入/越狱（`prompt_injection`）、恶意破坏性执行（`malicious_execution`）、凭据与数据窃取（`data_exfiltration`）、政治敏感（`politics`）、露骨色情（`pornography`）、暴力恐怖（`violence_terrorism`）、违禁违规（`contraband`）、欺诈赌博（`fraud_gambling`）、极端骚扰与恶意操纵（`harassment_manipulation`）。类别字段严格作为选择确定性脱敏文案模板（`SanitizedMessageForCategory`）的元数据，不直接参与风险高低策略路由。
  - **严格双向分类不变量（Category Invariant）**：强制维持 `category == none <=> risk_level == none` 双向等价强校验，杜绝任何有分类却无风险、或无分类却存在风险的非法结构。
  - **Reason 诊断字段严格隔离不变量（Diagnostic Reason Isolation Invariant）**：分类器返回的 `reason` 字段被严格限制为内部排障与审计诊断元数据（`meta.Reason`），绝对不参与下游策略路由分支，绝对不拼接到用户可见错误提示或主 LLM 上下文中。
  - **四级信息边界降级流水线（Four-Level Degradation Pipeline）**：
    - `none`（`WatchdogPass`）：原始内容完整无损放行进入主 LLM 及会话上下文/历史，不附加任何警告。
    - `medium`（`WatchdogWarn`）：原始内容完整保留传入下游主 LLM 及会话历史；在向主 LLM 发起请求时，动态向系统提示词（`RunContext.SecurityNotice`）注入受信任的中心化临时安全审查警告（`MediumRiskWarningNotice`），提示模型保持防御姿态与安全边界。此警告仅在模型推理阶段注入，绝对不写入持久化会话历史（`messages` / `Session.Snapshot`），杜绝长期上下文污染；不硬阻断，不施加惩戒。
    - `high`（`WatchdogFilter`）：下游丢弃原始内容，根据所属分类替换为中心化受控脱敏文案（`[FrostAgent 安全审查系统] <此内容已过滤：检测到...内容！请在后续对话中明确向用户说明安全边界。>`）；动作标记为 `WatchdogFilter`，后续正常驱动对话流与上下文（`GroupCompact`、会话历史与主 LLM 均仅接收脱敏文案），实现安全容错与引导。
    - `critical`（`WatchdogBlock`）：丢弃原始文本，直接阻断当前请求而不调用主 LLM，向触发者返回 `RejectInspectorMsg`；在群聊场景下，群精简上下文（`GroupCompact`）仅注入脱敏标记，确保上下文知晓发生了违规过滤而绝不暴露原始恶意载荷。
  - **阶梯式渐进处罚机制与来源溯源严格隔离（Graduated Enforcement Contract & Provenance Isolation）**：针对直接用户输入（`SourceUserDirect`）且经分类器判定为严重危害（`RiskLevelCritical`）的恶意请求，系统遵循 Issue #144 确立的阶梯式渐进处罚机制（Graduated Enforcement）：
    - **初次违规（First Offense）**：仅执行内容阻断（`WatchdogBlock`），记录被阻断内容哈希与时间（`LastBlockedAt`、`LastBlockedHash`），不累计 Strike 且不锁定用户（0 strikes, no lock）；
    - **时间窗口内重复/规避尝试（Repeated or Evasion Submissions in Strike Window）**：在惩罚窗口内（`strikeWindow`，默认 15 分钟），若用户重复提交相同恶意哈希的内容或进行主动编码混淆规避（`isEvasion == true`），累加 1 次违规警告（Strike），返回 `WatchdogStrike`；
    - **达到违规阈值触发封禁（Lock Threshold Reached）**：当 Strike 达到或超过锁定阈值（`strikes >= lockAfter`，默认 3 次），主体状态自动流转为 `AccessLocked` 并返回 `WatchdogLock`，在网关 Ingress 最前沿对后续请求直接实施全局封禁拦截（`RejectGatewayMsg`）。
    - **来源溯源与故障隔离的零惩罚不变量（Zero-Penalty Invariants for Non-Direct Origins & Failures）**：
      - 非直接来源隔离：非直接用户输入（包括 `USER_QUOTE_REPLY_CONTEXT`、`GROUP_CONTEXT`、`TOOL_ARGUMENT`、`TOOL_RESULT`、`MODEL_OUTPUT`、`VISION_RESULT`、`PLATFORM_METADATA`）命中风险时，仅执行内容脱敏/阻断，绝对不调用 `RecordBlockedSubmission`，严格保证 0 strikes 且不锁定触发请求的用户；
      - 风险等级隔离：良性、中风险（`medium` / `WatchdogWarn`）与高风险（`high` / `WatchdogFilter`）仅触发对应的提示词警告或内容脱敏过滤，绝不施加 Strike 或封禁处罚；
      - 基础设施与分类器故障隔离：网络断连、上游超时、JSON 格式错误及底层存储 I/O 故障严格执行 Fail-Closed 阻断（`WatchdogBlock`，`IsFailure: true`），同时严格保证零惩罚（0 strikes，不封禁）；
      - Dry-Run 模式隔离：Dry-run 评估仅产生审计模拟判定，不写入持久化状态，绝不累加 Strike 或触发锁定。
    - 保留管理员手动/管理锁定功能（`AccessStore.IsLocked`、`Lock`、`Unlock` 与控制面 `/api/security/locked`、`/api/security/unlock` REST 端点）。被管理员锁定的主体在 Ingress 最前沿即被拦截（`RejectGatewayMsg`）。
  - **双重分类评估强风险等级合并（Dual-Classification Strongest-Risk-Level Merge）**：当输入触发编码混淆而启动双重分类（原始文本与归一化文本）时，`Watchdog.EvaluateWithContext` 严格依据数值风险严重程度绝对序（`RiskLevelSeverity`: `critical (3) > high (2) > medium (1) > none (0)`）选取最强风险级别，坚决杜绝归一化文本较低风险（如 `medium` 或 `high`）意外覆盖或降级原始文本的高危判定（如 `critical` 降级为 `WARN` 或 `FILTER`），确保策略动作与脱敏文案类别始终反映两者的最高危险级别。
  - **入站唤醒/回复路由与内容脱敏解耦（Decoupling of Ingress Wake/Reply Routing from Content Sanitization）**：在平台适配器（OneBot、AstrBot）入站阶段，群聊唤醒判定（@机器人、别名唤醒、引用回复等路由信号）必须在**原始未修改的传输事件（Pristine Transport Event）**上计算并固化，严格与后续内容脱敏（`SanitizeOneBotMessage`、`event.Content` 替换）解耦。由于脱敏文案默认包含 `[FrostAgent 安全审查系统]`，若在判定前替换文本，将导致包含默认别名 `FrostAgent` 的脱敏标记使未唤醒的背景闲聊产生假唤醒（False Wake）与非预期回复；反之，若整包重写消息段则会破坏原始 `@` 与引用回复元数据造成漏唤醒（False Silence）。通过在脱敏前预先推导可信路由信号（`EventRouting` / `_frostagent_should_reply`），并仅替换消息段中的文本部分而保留结构化路由段（`at`、`reply`、图片等），彻底消除假唤醒与漏唤醒风险。
  - **按需入站安全审查门禁与背景闲聊解耦（Selective Wake-Triggered Ingress Security Gating & Background Chatter Decoupling）**：为彻底杜绝非唤醒群聊背景消息对 LLM 安全审查模型的无效调用、消耗 Token、触发上游限流及引入不必要的审查延迟，系统确立严格的按需入站安全审查不变量：**仅当入站消息明确唤醒模型以触发响应时，才调用 `GateIngress` 执行入站安全审查；未唤醒的背景消息完全不调用审查模型。**
    - **私聊场景**：所有私聊消息天然以模型回复为目的，始终作为显式唤醒消息进入入站安全审查。
    - **群聊场景**：仅在消息具备显式唤醒信号（包含真实 @ 机器人、或匹配机器人名称/别名唤醒词）且群聊回复开关未禁用（`GROUP_REPLY_ON_MENTION != "false"`）时，才调用 `GateIngress` 执行 LLM 审查。未唤醒的普通群聊背景闲聊完全绕过安全网关分类器，避免无谓的网络往返与成本开销。
    - **被动上下文摄入保持（Passive Group Compact Retention）**：未唤醒的背景群聊消息虽绕过安全网关审查，但依然无缝流向群精简上下文缓冲区（`captureGroupCompactMessage`），保持群聊多轮对话的被动背景语境记忆，确保后续被唤醒时具备准确的上下文理解，同时杜绝未唤醒背景对话产生审查开销。
    - **上游平台 RPC 保护与协议规范**：在 OneBot 适配器中，未唤醒的群聊消息在完成唤醒信号检测（`!wakeSignals.Any()`）后立即返回，严格禁止在判定未唤醒前发起用于引用回复解析的 `lookupReplyContext`（`get_msg` 平台 RPC），杜绝上游网络放大与资源消耗；在 AstrBot 协议中，未唤醒消息显式返回良性协议确认（`Action: "noop"`），明确其作为协议层静默确认而非对话回复的语义边界。
- **Watchdog 检查点与全链路上下文审查降级（Provenance Checkpoints & Context Vetting Degradation）**：
  Watchdog 覆盖直接用户入口（`USER_DIRECT`）、用户引用回复上下文（`USER_QUOTE_REPLY_CONTEXT`）、群聊摘要与近期群消息（`GROUP_CONTEXT`）、多模态视觉处理结果（`VISION_RESULT`）、平台元数据（群名、用户昵称、群名片等 `PLATFORM_METADATA`）、工具参数（`TOOL_ARGUMENT`）、工具返回结果（`TOOL_RESULT`）以及最终模型输出（`MODEL_OUTPUT`）全生命周期。所有非直接上下文在注入 LLM Prompt 前均必须经过独立 Checkpoint 审查：
  - 非直接上下文（引用回复、群摘要、图片描述、平台元数据等）评估命中 `high` 或 `critical` 时，执行上下文降级替换，将其替换为分类对应的中心化脱敏文案（`SanitizedMessageForCategory`）；命中 `medium` 时若未设置安全警告则注入 `MediumRiskWarningNotice`；遭遇基础设施故障（`IsFailure: true`）时执行 Fail-Closed 安全隔离（清空该字段）。所有辅助上下文风险均不惩罚触发请求的当前用户。
- **显式安全拦截报错与三态安全边界解耦（Inspector vs. Gateway vs. Service Failure）**：
  当用户请求被安全控制拦截时，不再静默丢弃（"一声不吭"），而是向用户返回具有明确安全责任边界的 FrostAgent 层面标准报错：
  - **安全审查员拦截（Security Inspector）**：当活跃用户的消息内容命中 Watchdog 阻断或违规规则时（`decision.IsFailure == false` 且 `decision.Action == WatchdogBlock`），返回：
    `FrostAgent 错误：Request rejected by security inspector: 不合适的内容！`
  - **安全网关封禁拦截（Security Gateway）**：当主体在安全访问控制网关中处于封禁/锁定状态（已在 `AccessStore` 中处于 `LOCKED` 状态，由管理员锁定或管理 API 锁定），返回：
    `FrostAgent 错误：Request rejected by security gateway: 您已被封禁，请联系管理员。`
  - **安全审查服务异常（Security Service Failure）**：当安全网关超时、上游模型断连、网络报错、返回畸形/非结构化 JSON、未配置网关或处于故障严格 Fail-Closed 状态时（`decision.IsFailure == true`），返回：
    `FrostAgent 错误：Request rejected by security service: 安全审查服务暂时不可用，请稍后重试。`
    系统杜绝在审查服务或分类器出现网络/上游故障时错误地以 `RejectInspectorMsg`（"不合适的内容！"）指控无辜用户，并在平台适配器层（OneBot、AstrBot）与 Controller 层面提供详尽的自动化回归测试。在系统日志中，内容拦截以 `Warn` 级别记录，而审查服务异常以 `Error` 级别记录。
  - **前置安全不变量与群聊礼貌拦截**：拦截报错在适配器 Ingress 入口最前沿发送（早于消息会话映射、群聊上下文缓冲、贴纸观察、视觉处理与 LLM 调用）；在私聊场景下始终返回报错；而在群聊场景中，仅当机器人被显式触发唤醒响应（@机器人或别名/唤醒词唤醒，且 `GROUP_REPLY_ON_MENTION != "false"`）时才发送拦截报错，避免在未艾特机器人的群聊背景对话中因出现敏感词或被封禁用户发言而产生非预期的机器人报错打扰。群聊唤醒判定严格限定于本地 Ingress 元数据，严禁在安全判定阻断后为解析引用回复发起 `get_msg` 等上游平台 RPC，杜绝针对被拦截主体的额外网络消耗与潜在滥用面。
- **模型最终输出与工具调用安全审查收束（Centralized Terminal Model Output & Tool Gate Inspection）**：
  模型最终回复（`StageModelOutput` / `MODEL_OUTPUT`）、工具调用入参（`StageToolArgument`）与工具执行结果（`StageToolResult`）的安全审查职责完全收束至 `llm.Engine`（`internal/llm/agent.go` 与 `securityEvaluate`）。`Engine` 保持 `decision.IsFailure` 与 `decision.EvaluationID` 的无损传递，严格区分策略违规阻断与上游审查服务异常：
  - **访问控制存储异常与主体封禁解耦**：在检查点执行 `securityEvaluate` 时，严格区分真实主体封禁（`errors.Is(accessErr, security.ErrLocked)`）与底层存储基础设施异常（如 `AccessStore.load` 读盘失败、损坏/畸形 JSON、未知文件版本或未配置存储）。基础设施故障产生 `IsFailure: true` 决策并生成对应阶段的 `EvaluationID`（如 `eval_model_output_*`），触发服务异常降级隔离与 `Error` 级别日志记录，绝不将底层存储读写故障混淆为用户策略锁定。
  - **模型输出策略违规阻断**（`!decision.IsFailure`）：替换为 `FrostAgent安全控制：模型输出已拦截。`，并在系统日志以 `Warn` 级别记录 `eval_id`。
  - **模型输出审查服务异常**（`decision.IsFailure`）：替换为 `FrostAgent安全控制：安全审查服务暂时不可用，模型输出已拦截。`，并在系统日志以 `Warn` 级别记录 `模型输出因安全审查服务异常被拦截: eval_id=%s`（根因详情由底层 Watchdog ERROR 日志唯一记录，外层不再重复记录 `error_type` 或 `reason`）。
  - **工具调用入参与工具结果检查点**：工具参数阻断区分常规策略阻断（`FrostAgent安全控制：该工具调用已被阻止。`）与审查服务异常（`FrostAgent安全控制：安全审查服务暂时不可用，该工具调用已被阻止。`，记录 Warn 级别 `工具入参因安全审查服务异常被阻止: tool=%s eval_id=%s`）；工具结果隔离亦区分策略隔离（`FrostAgent安全控制：外部工具结果已隔离。`）与审查服务异常（`FrostAgent安全控制：安全审查服务暂时不可用，外部工具结果已隔离。`，记录 Warn 级别 `工具结果因安全审查服务异常被隔离: tool=%s eval_id=%s`）。
  - **工具检查点中风险警告向请求局部上下文的动态传播（Tool Checkpoint Warning Propagation to Request-Local Context）**：在智能体多轮工具执行循环中，当工具入参（`StageToolArgument`）或工具执行结果（`StageToolResult`）的审查判定为中风险警告（`WatchdogWarn`）时，`Engine` 通过 `mergeSecurityNotice` 将警告提示（`decision.WarningNotice`）动态合并传播至请求局部的 `RunContext.SecurityNotice`，使当前轮次后续的 LLM 迭代请求在系统消息中即时注入 `MediumRiskWarningNotice` 强化对不信任参数或外部工具返回结果的安全防范，同时绝对不污染持久化会话快照（`Session.Snapshot`）。
  各平台适配器（OneBot、AstrBot 等）严禁在发送消息前对模型最终输出进行多余的二次重复分类调用。通过回归测试确保从 Ingress 审查到模型最终输出审查全链路中，模型输出仅经过一次且仅有一次确定的审查。
- **全链路安全评估关联与日志追踪（Evaluation Correlation & Trace ID Propagation）**：
  `Watchdog.EvaluateWithContext` 在审查开始时即生成全局唯一的评估关联追踪 ID（`EvaluationID`，如 `eval_<stage>_<hex>`），并同步注入 `AuditEvent.ID` 与 `WatchdogDecision.EvaluationID`。该评估 ID 穿透 `ClassificationInput.EvaluationID`，在基于 LLM 的安全分类器调用时作为 `core.ChatRequest.TraceID` 向下游传递。LLM 客户端（如 `openai.Client.Chat`）将 `req.TraceID` 完整记录到 `LLM_REQUEST` 与 `LLM_RESPONSE` 的结构化日志中，并贯穿透传至传输层网络错误（`HTTPClient.Do` 超时或断连）及非 200 HTTP 响应（如 429、500、503）的错误日志中；在适配器（OneBot、AstrBot）拦截日志中记录 `eval_id`。进一步地，ConnectRPC 服务契约（`api/proto/frostagent/v1/logs.proto` 中的 `LogEntry.trace_id = 9;`）与服务适配层（`internal/service/logs/service.go::convertEntry`）无损向下游转发 `TraceID`，并在 Web UI（`apps/web/src/pages/logs.ts`）的日志详情面板与实时流中以 Trace 徽标完整透出，实现端到端穿透溯源与可视化归因。
- **有界归一化与组合式规避解码（Compositional Normalization Pipeline）**：
  - Watchdog 设置明确的安全审查上限（256 KiB）。超出上限的超大输入直接 Fail-Closed 阻断，坚决杜绝静默截断放行导致的尾部走私注入。
  - 编码归一化采用容错百分号扫描器（`tolerantPercentUnescape`），按字节逐个解码有效的 `%[0-9a-fA-F]{2}` 序列，同时完整保留混杂的畸形转义（如 `%ZZ`、末尾悬空 `%`、未截断十六进制）和字面加号（`+`），彻底避免传统全有或全无解码器在遇到畸形字符时直接中断解码导致危险载荷漏检，并杜绝将 `C++` 或 `A+B` 误判为编码规避。
  - **多层组合归一化流水线**：采用有界循环（最多 3 轮），按层序依次瓦解复合规避手段：
    1. 容错百分号解码（`tolerantPercentUnescape`）；
    2. 全文 Base64 候选解码（`tryDecodeBase64`）；
    3. 嵌入式 Base64 候选替换（`replaceEmbeddedBase64`，识别 `echo <b64> | bash` 等混入明文命令中的 Base64 代码片段）；
    4. 不可见字符、零宽空格、双向文本控制符与标签符清除（`stripZeroWidthAndControl`）；
    5. 全角字符归一化（`0xFF01..0xFF5E -> 0x0021..0x007E`，且精准细分：全角字母与数字 `0xFF10..0xFF19` / `0xFF21..0xFF3A` / `0xFF41..0xFF5A` 判定为规避转换 `evasionModified`，全角标点符号与全角空格 `　` 判定为纯排版优化 `typographicModified` 并免除二次分类审查）；
    6. 数学花体与数学字母数字符号映射（`U+1D400..U+1D7FF -> ASCII A-Z, a-z`）；
    7. **混合语系西里尔同形字精准还原（`normalizeMixedScriptCyrillic`）**：针对利用西里尔字母 `о`、`е`、`а`、`р`、`с` 等与拉丁字母形似的混淆载荷（如 `ignоrе аll prеviоus`），仅在混合语系混淆词素中映射为 ASCII 拉丁字符，通过非同形原生西里尔字母特征精准识别并保留正规西里尔文本（如俄语、乌克兰语），杜绝破坏正常多语言处理。
- **对抗评估基准体系（Adversarial Evaluation Framework）**：
  - 新增 `internal/security/eval` 模块，提供标准测试语料（`TestCase`）与自动化评估测试套件（`EvalRunner`）。
  - **解耦确定性策略底座测试与语义网关评估**：
    - 针对确定性策略底座流水线（规避检测打标、跨实例并发锁定同步 `RunCrossInstanceConsistencySuite`、策略阈值分离 `TestPolicyThresholdsSeparation`），全量使用独立于生产代码的脚本化测试桩（`_test.go`），严格测试状态机转换、并发竞争和溯源隔离。
    - 针对语义安全分类器评估：
      - **流水线契约回归（`TestAdversarialCorpusPipelineContract`）**：在离线 CI 环境中使用确定性 Mock Provider 检验生产级 `*security.LLMClassifier` 完整流水线契约（XML 实体转义、Prompt 组装、JSON 反序列化、4 级风险级别与 10 受控分类结构校验、脱敏文案映射与 Watchdog 决策闭环）。此测试定位为工程管线回归测试，明确不声明为生产大模型的真实语义辨识质量指标。
      - **生产模型实测通道（`TestLiveGatewayAdversarialEvaluation`）**：提供独立的可选（opt-in）真机评测路径，当提供专用环境变量 `FROSTAGENT_SECURITY_EVAL_API_KEY`（或在显式开启 `FROSTAGENT_SECURITY_EVAL_LIVE=1` 时复用 `OPENAI_API_KEY`）时接入真实配置的 LLM 安全模型进行全量基准测试，实测并输出特定模型的误阻断率（False Block Rate）与严重漏检率（Severe Miss Rate）；未显式 opt-in 或无密钥时自动跳过（`t.Skip`），杜绝常规开发机因环境残留 `OPENAI_API_KEY` 而在无意中执行付费网络评测，不阻塞普通 PR CI。在执行具体生产模型评测前，语义模型质量指标保持未声明状态。
    - 配套网关故障与断连严格 Option A Fail-Closed 验证（`TestAdversarialCorpusEvaluation_GatewayFailClosed`），确保当上游 LLM 安全网关发生网络中断或超时时，所有请求严格被阻断（`BLOCK`，`IsFailure: true`）且不触发用户封禁（零惩罚不变量）。
  - 评测矩阵覆盖：
    - **误阻断率（False Block Rate）**：衡量良性科普、编程讨论、安全分析等查询被误拦或误降级的比例。
    - **严重漏报率（Severe Miss Rate）**：多语言越狱、破坏性命令与敏感信息窃取载荷漏检率。
    - **综合准确率（Accuracy）**：全语料决策匹配准确率（根据语料中显式定义的 `ExpectedAction`、`ExpectedRiskLevel` 与 `ExpectedCategory` 逐条严密断言，杜绝非预期放行或误报在未配置特殊标记时被静默统计为成功的缺陷）。
- **安全审计凭据脱敏与最小化存储**：安全审计日志记录（`security_audit.jsonl`）的摘要预览（`safePreview`）在截断前必须经过严格的凭据脱敏处理（Redaction），过滤 Bearer Token、URL 查询凭据、API Key（如 `sk-...`、`glpat-...`、`xoxb-...`）、GitHub 经典 PAT 及各类 Token（`ghp_`、`gho_`、`ghu_`、`ghs_`、`ghr_`）、GitHub 细粒度 PAT（`github_pat_...`）以及密码字段，防止敏感鉴权凭据持久化到本地日志造成横向移动风险。
- **统一工具边界与外部系统隔离**：Engine 公共工具循环在执行内置工具和 MCP 工具前审查参数，执行后隔离高风险工具结果，模型输出后进行出站审查，中间 SendHook 也经过严格管控。对于 ActionsCat 等外部自动化与持久化管理工具，进一步实施分层安全隔离（详细见 [actionscat.md](actionscat.md)）：
  - **管理面持久写权限门禁**：对具备控制面持久化修改语义的工具（包括 `actionscat_create_action`、`actionscat_create_version`、`actionscat_build_version`、`actionscat_activate_build` 及 `actionscat_deploy_action`），工具层强制提取 `llm.RunContext` 并通过 `admincmd.IsAdmin` 限制仅 `ADMIN_QQ_IDS` 允许调用，对无上下文或非管理员调用严格 Fail-Closed 并产生 0 次后端网络调用，防止聊天会话或 Prompt 注入绕过控制面身份验证；
  - **模拟会话零持久化副作用 (Zero Durable Mutation)**：在 `mock=true` 调试会话中，所有涉及外部系统持久化写入、构建与任务触发的工具（如 `actionscat_run_action` 及上述 5 项管理变更工具）一律 Fail-Closed 拦截，确保 0 次外部持久调用；
  - **构建未决结果与状态门禁**：同步编译构建采用独立长超时（180s），任何传输中断（连接重置、意外截断）、超时、HTTP 5xx 服务端错误（因 ActionsCat Core 先落盘持久化 Build 记录后执行沙箱编译）以及 2xx 响应不可解析均严格包装为 `ErrBuildUnknownResult`（映射为 HTTP 504 Gateway Timeout），阻断误报失败状态，并通过 `actionscat_list_builds` 引导 Agent 幂等排查后台状态（包含初次为空时的短暂重试查询建议）防止并发重复构建；激活构建必须断言 `build.Status == "succeeded"`，并在编译失败时输出截断日志与不可变版本新建指引；
  - **敏感凭据脱敏隔离**：外部任务系统执行结果暴露给模型前，严格采用 DTO 白名单过滤，彻底剥离持久状态注入项（如 `planned_env`），防止凭据泄露至大模型上下文；
  - **受保护运行环境变量防御**：工具层对传入的动态环境变量进行保留前缀黑名单校验（拦截 `ACTIONSCAT_*`），杜绝模型输出伪造沙箱内的受信任执行身份。
- **管理面板与控制面接口**：控制面根路径提供受 Bearer 认证保护的 `/api/security/locked` 与 `/api/security/unlock` REST 端点，与 MCP 控制面深度复用统一的 Scoped `instanceconfig.Store` 鉴权源，在无需将 Token 镜像到操作系统进程环境变量的配置存储模式下依然能够严格受控，配合 Web 控制台「安全控制」页提供全局锁定状态的可视化查看与人工解锁支持。
- **内部测试与 Synthetic Principal**：通用 `eval` / synthetic principal 概念保留用于内部 Watchdog 单元测试及未来的自动化测试 Harness；系统不暴露或维护任何面向第三方的 HTTP Evaluation API（如 `/v1/messages`），后续真实平台测试将通过新的 Telegram Adapter 完成。
- **细粒度系统错误可观测性与用户侧严格泛化不可用不变量（Detailed Error Observability & User-Facing Generalization Invariant）**：
  - 在所有安全故障处理点（`Watchdog.EvaluateWithContext`、`Controller.GateIngress`、`llm.Engine` 以及平台适配器 Ingress），系统错误日志（`logs.Error(logs.SYSTEM, ...)`）结构化记录具体的 Go 错误类型 `error_type=%s`（通过 `ErrorType(err)` 递归 `errors.Unwrap` 提取底层根因类型链条，如 `*fmt.wrapError[*os.PathError]` 或 `*json.SyntaxError`）以及经安全脱敏、控制字符规整与有界截断（限制在 256 字符，追加 `...` 后缀）的错误摘要 `reason=%s`（通过 `SafeErrorSummary(err)`，消除 Bearer Token、API Key、密码、URL 认证凭据与 `\r\n` 日志注入风险），并恒定保留上下文评估追踪 ID `eval_id=%s`。
  - **用户侧泛化不变量**：对外用户交互界面（`RejectMessage`、模型输出拦截提示、工具调用拦截响应等）严格仅向用户返回泛化的安全服务暂时不可用提示（`RejectFailureMsg` / `"FrostAgent安全控制：安全审查服务暂时不可用，请稍后重试。"`）。内部具体的底层错误类型、文件系统绝对路径、堆栈信息和原始报错文本被严格限制在内部系统错误日志中，绝对不向外部调用方泄漏，彻底杜绝恶意嗅探与内部基础设施信息侦察风险。
- **可配置安全网关超时与共享配置模型（Configurable Security Gateway Timeout & Shared Configuration Model）**：
  - 彻底移除了原先在 `LLMClassifier` 与 `Watchdog` 中硬编码的 5 秒超时（`5*time.Second`），有效避免在网络代理、模型冷启动或上游排队时产生激进的误判 Fail-Closed。
  - 设立标准生产默认超时 `DefaultClassifierTimeout = 15 * time.Second`，并引入真正的共享配置归属模型（`instanceconfig.SharedKeys`，覆盖 `SECURITY_GATEWAY_TIMEOUT` 与 `SECURITY_CLASSIFIER_TIMEOUT`），允许在全局（`global.env`）与实例（`instance.env`）两个作用域内同时读写、持久化与通过 `SettingsService` API 管理，并同时注册至 `InstanceRestartKeys` 与 `ControlPlaneRestartKeys`。
  - 严格执行层级解析优先级：`实例覆盖（instance override） > 全局配置（global config） > 进程环境变量（process env） > 默认值（15s）`。
  - 配置时长经过严密校验（`ValidateClassifierTimeout` 与 `NormalizeClassifierTimeout`）：遇到非正数（<=0）、格式非法或空字符串时安全回退至默认值（15s），杜绝系统 panic。
  - 保持严格 Fail-Closed 与零惩罚不变量：当发生真实上下文超时（`context.DeadlineExceeded`）或网络取消时，请求被严格判定为基础设施故障并阻断（`WatchdogBlock`，`IsFailure: true`），完全不累计 strike 且永不锁定账户。
- **两层端到端日志去重架构（Two-Tier End-to-End Log Deduplication Architecture）**：
  - 彻底解决同一底层安全故障在入口适配器和 Engine 各个非入口检查点被重复记录两次完整 ERROR 或漏记详细根因的日志泛滥/黑洞问题，确立严格的分层责任：
    1. **根因层（`Watchdog` 分类器 / `securityEvaluate` 访问控制门禁）**：负责记录真实故障根因，作为**唯一**记录底层详细故障的组件输出 `ERROR` 级别日志（分类器异常：`安全审查分类器异常 (Fail-Closed): error_type=%s reason=%s eval_id=%s`；存储/权限访问异常：`安全控制存储状态异常 (Fail-Closed): principal=%s error_type=%s reason=%s eval_id=%s`），包含具体 `error_type`、脱敏截断的 `reason`、关联 `eval_id` 以及访问主体 `principal`，并对未脱敏的模型原始输出、API Key/Token（如 `sk-...`）以及敏感凭据进行严格过滤、`[REDACTED]` 替换和有界截断。
    2. **入口适配层（`OneBot`、`AstrBot` 等平台适配器）**：仅记录该次业务请求因安全审查服务不可用而被拒绝，输出 `WARN` 级别业务日志（`<Adapter> 请求因安全审查服务异常被拒绝: user=%s eval_id=%s`），严禁重复输出底层 `error_type` 和原始 `reason`。
    3. **Engine 非入口检查点（`llm.Engine`）**：在 `MODEL_OUTPUT`、`TOOL_ARGUMENT`、`TOOL_RESULT` 阶段仅记录阶段/工具与评估 ID 的上下文 `WARN` 级别日志（`模型输出因安全审查服务异常被拦截: eval_id=%s`、`工具入参因安全审查服务异常被阻止: tool=%s eval_id=%s`、`工具结果因安全审查服务异常被隔离: tool=%s eval_id=%s`），绝不重复记录 `error_type` 或 `reason`。
  - 所有层级严格共享全局唯一的 `eval_id`，在杜绝冗余重复日志的同时确保全链路审计的精确关联。

该体系的核心不变量是：全局锁定状态在所有适配器 Ingress 阶段（早于群聊压缩、贴纸观察、会话锁、视觉处理及 LLM 调用）和 Engine 执行入口立即生效；被锁定的主体绝对无法进入任何业务流转。

## Multi-instance Architecture and Platform Foundation

The Control Plane owns one persistent security Controller at the global data root and injects that same Controller into every instance Runtime and Engine. Consequently, a lock created through any instance or adapter is visible immediately to all other instances and transports, while audit records retain the actual instance, session, stage, and provenance source identifiers.

Key design guarantees:
1. **Scope**: Global Access Control + Watchdog foundation for all FrostAgent platform adapters. (Telegram Adapter and Telegram-based adversarial E2E testing are tracked separately and not part of this foundation PR).
2. **Platform Canonicalization**: Decouples transport protocol names (`onebot`, `aiocqhttp`) from user principals (`qq:<user_id>`), guaranteeing that security policies and lock states apply to the human actor across transports.
3. **Pure LLM Gateway Architecture & Option A Fail-Closed**: Completely removed local semantic content classification (`CalibratedClassifier`) and `HybridClassifier` from the codebase. Semantic risk evaluation is exclusively delegated to the LLM security gateway (`*LLMClassifier` via `core.LLMProvider` with XML entity escaping across `&`, `<`, `>`, `"`, `'` to guarantee delimiter breakout immunity). When no LLM provider is configured (or provider is nil), the system strictly fails closed under Option A (`BLOCK`, zero strikes, no lock). Deterministic plumbing (normalization, provenance tracking, content hashing, evasion bookkeeping, limits, access store, audit) is preserved. In multi-instance runtimes, security classifier providers are scoped per-instance (`SetInstanceProvider`/`RemoveInstanceProvider`) as direct `*LLMClassifier` instances and synchronized via `sync.RWMutex`, eliminating interface data races under concurrent reloads while preserving unified global `AccessStore` and `AuditStore` semantics.
4. **Strict Structural Validation & Invariants**: LLM JSON classifications are parsed into pointer fields (`*string`) and rigorously validated to ensure all required fields (`category`, `risk_level`) are present and non-empty. Obsolete fields (`confidence`, `intent`, `platform_policy`) are completely eliminated. Invariant: `category == none <=> risk_level == none`. Empty objects `{}` or omitted fields cause strict error propagation and fail-closed blocking. Reason field is strictly isolated as internal diagnostic metadata and never participates in policy routing or user-visible responses.
5. **Zero-Penalty Fault Isolation Invariant & Storage Fail-Closed (Option A Fail-Closed)**:
   - **Classifier Fault Isolation**: When classifier evaluation encounters timeouts, provider disconnections, upstream errors, or malformed JSON responses, `Watchdog` unconditionally executes `WatchdogBlock` (`IsFailure: true`) with fail-closed reason. Automated strike accumulation is strictly bypassed on classifier failures (`RecordBlockedSubmission` is not called). Strike counts remain at 0 and accounts are never locked, guaranteeing complete fault isolation between upstream provider failures and user penalty state across repeated retries.
   - **AccessStore Persistence & State Fail-Closed**: When `AccessStore` encounters storage/persistence failures during state inspection or historical hash lookup (e.g., disk full, corrupted JSON, atomic replacement failure, lock timeout, or unconfigured store), `Watchdog` refuses to silently degrade to an ordinary content policy block (`IsFailure: false`). Instead, it strictly fails closed as an infrastructure failure (`WatchdogBlock`, `IsFailure: true`, zero strikes, no lock), preserves the correlation `EvaluationID`, logs a system `Error` event (`安全控制存储状态异常`), and returns `RejectFailureMsg` to the user. Similarly, `AccessStore.LastBlockedHash` propagates storage errors rather than silently swallowing them as empty history; any storage error during history verification fails closed with `IsFailure: true` and system `Error` logs.
6. **Ingress Single-Call Path Optimization & Typographic Decoupling**: `Watchdog.EvaluateWithContext` decouples security evasion transformations (`EvasionModified`) from harmless typographic normalization (`TypographicModified`). Plain inputs and inputs containing only harmless full-width Chinese/CJK punctuation (e.g. `，` `U+FF0C`, `？` `U+FF1F`, `！` `U+FF01`, `：` `U+FF1A`, `；` `U+FF1B`, `（` `）`, `～`) or ideographic spaces (`U+3000`) are not flagged as evasion attempts (`evasionModified == false`) and evaluate through the security LLM exactly once, reducing gateway latency and token cost by 50%. A second classification call against raw content is dispatched only when genuine security-relevant evasion transforms take place (zero-width characters, BiDi directional marks, Unicode tags, mathematical alphanumeric runes, full-width alphanumeric letters/digits `0xFF10..0xFF19` / `0xFF21..0xFF3A` / `0xFF41..0xFF5A`, mixed-script Cyrillic homoglyphs, percent decoding, or Base64 decoding) to detect evasion and record it in audit event metadata (`Event.Encoded = isEvasion`). Should this second raw-form classification encounter any error or timeout, Option A strict fail-closed unconditionally blocks the request while bypassing user penalties (0 strikes, no lock).
7. **Information-Boundary Degradation Pipeline & Graduated Enforcement Contract**:
   - **Single Policy Determinant**: `risk_level` (`none`, `medium`, `high`, `critical`) is the sole determinant governing how content is handled across security boundaries. Complete elimination of `confidence`, `intent` (`IntentMalicious`, `IntentBenign`, `IntentAmbiguous`), and generic `platform_policy`.
   - **Controlled Category Enum**: 10 strictly defined categories (`none`, `prompt_injection`, `malicious_execution`, `data_exfiltration`, `politics`, `pornography`, `violence_terrorism`, `contraband`, `fraud_gambling`, `harassment_manipulation`), serving exclusively as metadata to select deterministic sanitized replacement messages (`SanitizedMessageForCategory`).
   - **Strict Structural Invariants**: Enforces bidirectional equivalence `category == none <=> risk_level == none`. Diagnostic `reason` is strictly isolated as internal metadata, never participating in policy routing or user-visible responses.
   - **Four-Level Degradation Handling**:
     - `none`: Raw content passes into main LLM and context/history unchanged; no warning notice.
     - `medium`: Raw content passes into main LLM and context/history; injects a temporary trusted warning notice (`MediumRiskWarningNotice`) into the main LLM request system prompt (`RunContext.SecurityNotice`) without polluting persisted session history; no hard rejection, no punishment.
     - `high`: Raw text is discarded downstream; replaced with centralized category-specific sanitized message (`[FrostAgent 安全审查系统] <此内容已过滤：检测到...内容！请在后续对话中明确向用户说明安全边界。>`); dialogue continues normally using sanitized text (`WatchdogFilter`).
     - `critical`: Raw text is discarded downstream; request rejected at ingress without calling main LLM (`WatchdogBlock`); group compact context buffer receives only the sanitized marker.
   - **Graduated Enforcement Contract & Provenance Isolation**: For direct, attributable user submissions (`SourceUserDirect`) classified as critical risk (`RiskLevelCritical`), Watchdog restores the graduated enforcement contract (Issue #144):
     - Attempt 1 (First Offense): Content is blocked (`WatchdogBlock`), 0 strikes recorded, actor remains unlocked.
     - Repeated malicious attempts (same hash) or active encoding evasion (`isEvasion == true`) within `strikeWindow` (default 15 minutes): Increments strike count and returns `WatchdogStrike`.
     - Threshold reached (`strikes >= lockAfter`, default 3): Transitions principal state to `AccessLocked`, returns `WatchdogLock`, immediately enforcing a global gateway ban (`RejectGatewayMsg`) on subsequent ingress requests.
     - Non-direct sources (`USER_QUOTE_REPLY_CONTEXT`, `GROUP_CONTEXT`, `TOOL_ARGUMENT`, `TOOL_RESULT`, `MODEL_OUTPUT`, `VISION_RESULT`, `PLATFORM_METADATA`), benign/medium/high risk levels, dry-run evaluations, and storage/classifier outages are strictly isolated and never accrue strikes or locks (zero-penalty invariant).
     - Manual administrative access control (`AccessStore.IsLocked`, `Lock`, `Unlock`, `/api/security/locked`, `/api/security/unlock`) is fully preserved.
   - **Dual-Classification Strongest-Risk-Level Merge**: When evasion-obfuscated input triggers dual classification (raw text and normalized text), `Watchdog.EvaluateWithContext` merges decisions strictly by numeric risk severity ranking (`RiskLevelSeverity`: `critical (3) > high (2) > medium (1) > none (0)`). A lower risk level from the normalized classification (e.g. `medium` or `high`) can never overwrite or downgrade a higher risk from the raw evaluation (e.g. downgrading `critical` to `WARN` or `FILTER`). The merged decision adopts the highest severity across both evaluations for both policy action and sanitized category selection.
8. **Decoupling of Deterministic Policy Plumbing and Gateway Evaluation**: All local semantic content classifiers have been completely deleted from the codebase. Policy plumbing tests (cross-instance concurrency synchronization, access control state machines, and normalization suites) use lightweight scripted test doubles defined exclusively in `_test.go` files (`RunCrossInstanceConsistencySuite`, `TestPolicyThresholdsSeparation`). The adversarial evaluation framework (`internal/security/eval`) strictly separates offline pipeline contract regressions (`TestAdversarialCorpusPipelineContract`) using mock providers from opt-in live model evaluations (`TestLiveGatewayAdversarialEvaluation`). Live evaluation strictly requires an explicit opt-in signal (`FROSTAGENT_SECURITY_EVAL_API_KEY`, or `FROSTAGENT_SECURITY_EVAL_LIVE=1` alongside `OPENAI_API_KEY`), preventing ambient standard provider credentials from unexpectedly triggering paid/networked tests during ordinary `go test ./...`. Semantic quality metrics (false-block and severe-miss rates) depend on the configured production model and are measured via the opt-in live path, leaving semantic-model metrics explicitly unclaimed in offline CI until an actual production run is conducted.
9. **Indirect Context Checkpoints & Context Vetting Degradation**: Injected prompt context (quoted reply messages, group running summaries, image descriptions, and recent group history) is vetted via distinct Watchdog provenance sources (`USER_QUOTE_REPLY_CONTEXT`, `GROUP_CONTEXT`, `VISION_RESULT`). Auxiliary contexts evaluating to `High` or `Critical` risk are degraded by substituting raw text with category-specific sanitized messages (`SanitizedMessageForCategory`), while `Medium` risk injects temporary warning notices. Infrastructure failures fail closed by isolating (clearing) the auxiliary context, strictly protecting downstream components without penalizing the calling user.
10. **Graduated Information-Boundary Control & Enforcement**: Instead of binary intent-based blocking, FrostAgent regulates information flow across security boundaries according to 4 graduated risk levels (`none` -> `medium` -> `high` -> `critical`). Content at medium risk alerts the main LLM without mutating session state; high risk sanitizes content in-place; critical risk blocks direct interaction and sanitizes context buffers, while escalating repeated direct user attacks into strikes and locks via the graduated enforcement contract.
11. **Bounded Compositional Normalization**: Multi-pass pipeline uncovering embedded Base64, Cyrillic lookalikes in mixed scripts, mathematical stylized runes, fullwidth alphanumeric characters, and zero-width/control characters without ReDoS vulnerabilities, while decoupling harmless typographic normalization (full-width punctuation, ideographic spaces) to prevent false evasion classifications.
12. **Adversarial Evaluation Framework**: Native evaluation runner (`internal/security/eval`) decoupling offline pipeline contract regressions (`TestAdversarialCorpusPipelineContract`) from opt-in live LLM security gateway evaluations (`TestLiveGatewayAdversarialEvaluation`), measuring False Block Rate, Severe Miss Rate, and decision accuracy across the 4 risk levels and 10 categories against live production models without gating ordinary PR CI, complemented by strict fail-closed outage verification.
13. **Fail-Closed Atomic Persistence & Error Propagation**: Windows `MoveFileExW` and POSIX atomic renames prevent corrupted or missing security state files from failing open under high concurrency. All `AccessStore` methods—`IsLocked`, `Lock`, `Unlock`, and `LastBlockedHash`—explicitly propagate underlying I/O, parsing, and atomic replacement errors rather than silently masking them as benign defaults, guaranteeing deterministic fail-closed safety throughout the storage lifecycle.
14. **Explicit Security Rejections & Tri-State Boundary Decoupling**: Security interventions return explicit FrostAgent-level error notifications rather than dropping requests silently, strictly decoupling content policy rejections, user lockouts, and infrastructure/classifier outages:
   - Content policy violation for active principals (`decision.IsFailure == false` and `decision.Action == WatchdogBlock`): `FrostAgent 错误：Request rejected by security inspector: 不合适的内容！`
   - Banned/locked principals at the gateway (administratively locked in `AccessStore`): `FrostAgent 错误：Request rejected by security gateway: 您已被封禁，请联系管理员。`
   - Security classifier or infrastructure failures (`decision.IsFailure == true`, e.g. upstream timeout, network errors, malformed/non-structural JSON, or unconfigured gateway): `FrostAgent 错误：Request rejected by security service: 安全审查服务暂时不可用，请稍后重试。`
   In group chats, rejection notifications are sent only when the bot was explicitly addressed locally (via `@bot` or name wake word with group replies enabled), preventing unsolicited interruptions during unaddressed background conversations. The decision relies exclusively on ingress-local metadata and strictly avoids upstream platform RPCs (such as OneBot `get_msg` for quoted reply resolution) on behalf of rejected principals. Adapter ingress logs failure outages at `Error` level and content policy blocks at `Warn` level.
15. **Centralized Terminal Model Output & Tool Gate Inspection**: Security verification of terminal model outputs (`StageModelOutput` / `MODEL_OUTPUT`), tool arguments (`StageToolArgument`), and tool results (`StageToolResult`) belongs exclusively to `llm.Engine` (`securityEvaluate` in `internal/llm/security_gate.go` and execution loops in `agent.go`). The engine preserves `decision.IsFailure` and `decision.EvaluationID`, strictly differentiating content policy blocks from classifier/service failures:
   - Checkpoint evaluations distinguish genuine access locks (`errors.Is(accessErr, security.ErrLocked)`) from underlying storage/infrastructure failures (e.g. `AccessStore.load` I/O read failure, malformed JSON, unsupported schema versions). Pre-Watchdog storage errors at `securityEvaluate` emit a sanitized detailed root-cause `ERROR` log (`安全控制存储状态异常 (Fail-Closed): principal=%s error_type=%s reason=%s eval_id=%s`), produce `IsFailure: true` decisions with a stage-specific `EvaluationID` (e.g. `eval_model_output_*`), and bubble up to the outer Engine loop which emits exactly one contextual `WARN` log (`eval_id` + stage/tool) without duplicating error types or reasons, strictly avoiding false policy lockout classifications.
   - Model output policy blocks (`!decision.IsFailure`) replace output with `FrostAgent安全控制：模型输出已拦截。` and log `eval_id` at `Warn`.
   - Model output service failures (`decision.IsFailure`) replace output with `FrostAgent安全控制：安全审查服务暂时不可用，模型输出已拦截。` and log stage/eval_id context at `Warn` level (`模型输出因安全审查服务异常被拦截: eval_id=%s`), while root-cause ERROR reporting is emitted exactly once at the underlying failure layer (`Watchdog` for classifier errors or `securityEvaluate` for pre-Watchdog access store errors).
   - Tool arguments and tool results similarly distinguish policy blocks (`FrostAgent安全控制：该工具调用已被阻止。` / `FrostAgent安全控制：外部工具结果已隔离。`) from service outages (`FrostAgent安全控制：安全审查服务暂时不可用，...`) and log context at `Warn` level with tool and `eval_id`, omitting duplicated root cause strings.
   - **Tool Checkpoint Warning Propagation to Request-Local Context**: When intermediate tool checkpoints (`StageToolArgument` and `StageToolResult`) evaluate to medium risk (`WatchdogWarn`), `Engine` dynamically propagates the warning notice (`decision.WarningNotice`) into the request-local `RunContext.SecurityNotice` via `mergeSecurityNotice`. This ensures subsequent LLM iterations within the current execution turn receive `MediumRiskWarningNotice` in system messages to maintain defensive posture against untrusted tool inputs or tool outputs, while strictly avoiding pollution of the persisted session history snapshot (`Session.Snapshot()`).
   Transport adapters (OneBot, AstrBot, etc.) do not re-evaluate model outputs, eliminating redundant classifications and ensuring exactly one inspection per response lifecycle.
16. **Evaluation Correlation & Trace ID Propagation**: `Watchdog.EvaluateWithContext` generates a cryptographically random evaluation correlation identifier (`EvaluationID`, e.g., `eval_<stage>_<hex>`) on evaluation entry. This ID propagates through `WatchdogDecision.EvaluationID`, `AuditEvent.ID`, `ClassificationInput.EvaluationID`, and `core.ChatRequest.TraceID`. Downstream LLM providers (e.g. `openai.Client.Chat`) log this `TraceID` into `LLM_REQUEST` and `LLM_RESPONSE` structured logs, and thread `req.TraceID` through `HTTPClient.Do` network transport errors and non-200 HTTP responses (e.g. 429, 500, 503). Adapters record `eval_id` upon ingress rejection. Furthermore, the ConnectRPC proto contract (`api/proto/frostagent/v1/logs.proto::LogEntry.trace_id`), Go service layer (`convertEntry`), and Web UI (`apps/web/src/pages/logs.ts`) fully preserve and surface `TraceID`, enabling unambiguous end-to-end trace attribution across concurrent ingress, tool, context, and output inspections.
17. **Detailed Error Observability & User-Facing Generalization Invariant**: Across all fail-closed security failure checkpoints (`Watchdog.EvaluateWithContext`, `Controller.GateIngress`, `llm.Engine`, and platform adapters), system error logs (`logs.Error(logs.SYSTEM, ...)`) structuredly log concrete Go error types (`error_type=%s` via `ErrorType(err)` unwrapping root causes, e.g. `*fmt.wrapError[*os.PathError]` or `*json.SyntaxError`) and safely sanitized, control-character-normalized, length-bounded summaries (`reason=%s` via `SafeErrorSummary(err)` bounded to 256 runes), while preserving correlation `eval_id=%s`. Simultaneously, the **User-Facing Generalization Invariant** guarantees that external clients strictly and exclusively receive generalized service unavailable responses (`RejectFailureMsg` / `"FrostAgent安全控制：安全审查服务暂时不可用，..."`). Detailed Go error types, filesystem paths, and internal error strings are strictly confined to internal diagnostic error logs and never leak to external callers, eliminating reconnaissance and infrastructure probing attack vectors.
18. **Configurable Security Gateway Timeout & Shared Configuration Model**:
   - Replaced legacy hardcoded 5-second timeouts (`5*time.Second`) in `LLMClassifier` and `Watchdog` with a production-grade configurable timeout architecture (`DefaultClassifierTimeout = 15 * time.Second`), preventing aggressive false fail-closed rejections under network proxies, model cold-starts, or upstream queuing.
   - Introduced a genuine shared configuration ownership model (`instanceconfig.SharedKeys` covering `SECURITY_GATEWAY_TIMEOUT` and `SECURITY_CLASSIFIER_TIMEOUT`), enabling persistence and management across both global (`global.env`) and instance (`instance.env`) stores and through the `SettingsService` API, registered in both `InstanceRestartKeys` and `ControlPlaneRestartKeys`.
   - Strict resolution precedence: `Instance override > Global config store > Process environment variables > DefaultClassifierTimeout (15s)`.
   - Duration inputs are safely validated via `ValidateClassifierTimeout` and `NormalizeClassifierTimeout`: non-positive, zero, or malformed values fall back safely to the 15s default without panics or crashes.
   - Real `context.DeadlineExceeded` timeouts strictly preserve Option A Fail-Closed semantics: the request is blocked (`WatchdogBlock`, `IsFailure: true`), strikes remain 0, and user accounts are never penalized or locked.
19. **Two-Tier End-to-End Log Deduplication Architecture**:
   - Resolved duplicate full ERROR logging or unlogged failure root causes across gateway, adapter, and engine checkpoints through decoupled tiering:
     - **Root-Cause Tier (`Watchdog` / `Classifier` / `securityEvaluate` Pre-Watchdog Gate)**: Sole component emitting full root-cause details at `ERROR` level (`安全审查分类器异常 (Fail-Closed): error_type=%s reason=%s eval_id=%s` for classifier failures, and `安全控制存储状态异常 (Fail-Closed): principal=%s error_type=%s reason=%s eval_id=%s` for access store failures), with raw model outputs, tokens (`sk-...`), and sensitive credentials strictly sanitized and redacted to `[REDACTED]`.
     - **Adapter Ingress Tier (`OneBot`, `AstrBot`)**: Logs business rejection context at `WARN` level (`<Adapter> 请求因安全审查服务异常被拒绝: user=%s eval_id=%s`), completely omitting duplicated `error_type` and `reason`.
     - **Engine Non-Ingress Checkpoints (`llm.Engine`)**: Logs stage/tool context at `WARN` level (`MODEL_OUTPUT`, `TOOL_ARGUMENT`, `TOOL_RESULT`), recording only the stage, tool, and `eval_id` without duplicating root cause strings.
   - All layers correlate deterministically through the shared `eval_id`, eliminating log noise while ensuring complete end-to-end traceability.
20. **Decoupling Ingress Wake/Reply Routing from Content Sanitization**: Transport adapters (OneBot, AstrBot) derive group wake signals (`@bot`, alias/name matches, quote-reply context) and reply routing strictly from the **pristine transport event** before any content sanitization occurs. Because sanitized content contains `[FrostAgent 安全审查系统]` and default bot aliases include `FrostAgent`, sanitizing message text prior to routing evaluation causes unwoken background group chatter to trigger false alias wakes and unsolicited replies. Conversely, replacing structured message segments erases original `@bot` and reply tokens, causing legitimate addressed messages to become unwoken under custom aliases. Deriving immutable routing decisions (`EventRouting` in OneBot, `_frostagent_should_reply` metadata in AstrBot) on pristine events while preserving structural message segments (`at`, `reply`, images) during text sanitization guarantees immunity against both false wakes and false silence.
21. **Unified Tool Boundary & External System Isolation**: The engine execution loop vets tool arguments and isolates high-risk tool results. External tools with administrative or persistent side-effects (e.g. ActionsCat management and execution tools detailed in [actionscat.md](actionscat.md)) enforce strict caller authorization gates (`admincmd.IsAdmin` via `ADMIN_QQ_IDS`), fail closed with zero durable mutation during mock debug sessions (`mock=true`), handle synchronous build uncertainties idempotently via `ErrBuildUnknownResult`, sanitize sensitive environment items (`planned_env`) before model ingestion, and blacklist reserved runtime environment prefixes (`ACTIONSCAT_*`).
22. **Selective Wake-Triggered Ingress Security Gating & Background Chatter Decoupling**: To eliminate token wastage, API rate-limiting risks, unnecessary latency, and redundant model calls caused by indiscriminately classifying all ingress traffic, the system establishes a strict selective ingress gating invariant: **LLM ingress security review (`GateIngress`) is triggered if and only if an inbound message explicitly wakes the model to generate a response.**
    - **Private Messages**: All private messages naturally intend a direct model response and therefore always enter `GateIngress` security vetting.
    - **Group Messages**: Evaluated strictly based on explicit local wake signals (direct `@bot` mention or configured name/alias wake word) under enabled group replies (`GROUP_REPLY_ON_MENTION != "false"`). Unwoken background group chatter completely bypasses the LLM security classifier.
    - **Passive Group Compact Retention**: Non-woken background messages bypass LLM classification but continue to flow into the passive running group compact buffer (`captureGroupCompactMessage`), preserving situational group context and conversational memory without incurring review costs or token consumption.
    - **Upstream Platform RPC Protection & Protocol Semantics**: In OneBot, unwoken group messages immediately return upon detecting no wake signals (`!wakeSignals.Any()`), strictly preventing the dispatch of upstream `lookupReplyContext` (`get_msg` platform RPC) and eliminating platform RPC amplification. In AstrBot, unwoken messages receive an explicit benign protocol acknowledgment (`Action: "noop"`), solidifying its semantics as a transport-level acknowledgement rather than an active dialogue response.
