# 数据库兼容实现

当前规范为 [ADR-0002：v1 数据库基线](../../docs/adr/0002-v1-database-baseline.md)，使用方式及字段演进规则见[数据库版本兼容说明](../../docs/version-compatibility.md)。ADR-0001 的开放式目标已由该有界实施契约替代。

## 版本与迁移

`schema_meta.version=20` 是清理后的 v1 关系结构基线，`min_compatible_version=20` 阻止旧二进制误写。v7–v19 历史定义不改写；v20 清理、固定载荷表、模块迁移登记及版本推进在同一事务提交。新库直接构造最终结构。按 Maintainer 决定，4 张退休模型表及对话 scene/relation、记忆 visibility 直接删除，不归档；现用 provider 数据、凭据和记忆作用域保留。

`module_migrations` 继续使用稳定 ID 记录独立附加迁移，已有 endpoint / Computer Use 记录保持，增加 `opaque-instance-payloads/v1`。历史核心序列继续作为升级桥，不通过伪造历史 checksum 或改写旧版本来迁移。后续模块只变更载荷格式不必增加核心版本；核心结构不兼容时追加迁移并提高下限。

## 固定模块协议

`module_payloads` 以实例、模块和记录组成复合主键，以实例 ID 外键级联删除。base64 TEXT 在 SQLite/PostgreSQL 中均保存精确字节；SHA-256 校验完整性。新功能使用模块内部格式版本，信封和物理列保持不变。

存储 API 提供 insert-only、匹配原格式与摘要的条件更新/删除；禁止降级格式。恢复在空目标写入，强制要求重新绑定；普通保存不清除绑定标记。模块数据不得包含不适合导出的凭据，未知字节不能由通用层自动脱敏。

ZIP 固定成员 `modules.json` 传递模块记录；解码先检查信封、格式号、ID、重复项、校验和及配额。任意未知 ZIP 成员继续报错。完整备份在 SQLite 读事务 / PostgreSQL REPEATABLE READ 事务内读取全部 SQL 数据；文件字节仍按现有安全路径与大小规则读取。恢复失败清理新实例和模块，并按原规则恢复共享模型目录。

此版本不定义附着核心行的通用扩展机制；独立模块不能假定记忆/对话 ID 永远存在或不会复用。

## 兼容校验

未来版本在下限允许且布局可验证时原位使用，不改低版本号。完整操作校验实际能力，不再把高版本号本身当作失败原因：

- 核心和载荷表必须匹配列名/类型集合、主键、非空、唯一和外键；SQL 写入均指定列名，物理列顺序不影响契约。
- PostgreSQL 拒绝未知可延迟键、排斥约束、生成/identity 属性、CHECK、触发器、rewrite rule 与启用的 RLS；关系按实际 OID 解析，包含 search_path 和跨 schema 依赖。
- SQLite 拒绝未知约束和触发器；CHECK 检查忽略字符串与注释。
- 可变核心行和 Embedding 缓存不能被未知模块外键依赖。仅不可变实例 ID 可用于普通操作的独立模块关联；完整操作还拒绝跨 schema 的实例关联。
- 有数据的未知 SQL 表阻止完整备份/恢复/删除，避免宣称导出了不认识的数据。普通兼容读写仍可保留安全的独立 SQL 表。
- 原始无兼容声明 Computer Use v15 仅在历史列、默认值、约束和模块布局核对通过后回填下限，再正常升级。该历史默认值校验仍保留。
- 已知业务 JSON 的新增键、枚举和语义并不自动兼容。应先发布保留式写入器或提高下限。

## 验证

SQLite 单元测试与 Linux PostgreSQL CI 覆盖升级保留、失败回滚、独立模块原始字节、未知格式防覆盖、恢复绑定、实例隔离、删除清理及一致快照。既有跨 schema / RLS / rule / trigger / 默认值 / 缓存布局测试保留。

跨版本 CI 保留固定 v15/v16 二进制的历史往返，并升级到当前基线验证拒绝旧程序不改库。独立未来格式写入器不导入当前 storage/backup/instance 实现，以原始 SQL 写入格式 9，再验证当前程序完整往返后原始字节、摘要、格式和绑定状态。它是协议生产者测试，不是假称已发布的未来产品版本。

未配置 PostgreSQL DSN 的跳过不算验证成功。测试均使用临时数据库，不访问部署中的真实数据，不安排 Windows Smoke。
