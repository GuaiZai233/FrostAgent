# 运行信息指令

设置 → 指令设置顶部的“输出FrostAgent默认运行信息”默认开启。
对应实例配置 `ENABLE_RUNTIME_STATUS_COMMAND`，只有显式 `false` 关闭；清除配置恢复默认开启，保存后立即生效，无需重启实例。

任意群成员发送当前正文恰好为 `#fa`（忽略首尾空白，可带真实 @Bot 或引用标记），即可收到固定文本：

```text
FrostAgent 运行状态
[ 200 OK ]
Arch: amd64
Uptime: 233d 21h 16m

Ver: 1.0.0
```

- 只识别小写完整指令；子串、引用正文、历史消息、图片附件和 @其他人不触发。私聊不属于此指令。
- `Arch` 是正在运行的 Go 二进制架构，`Uptime` 是当前实例本次启动的时长，按天/时/分截断；不是宿主机时长。
- `[ 200 OK ]` 仅表示诊断处理器成功响应，不代表模型、数据库或外部服务健康。
- 不要求管理员或 @，独立于群聊回复和模型路由开关，不进入对话会话、记忆、Bot 连续回复预算、安全分类模型或外部消息分发器。
- 仍检查可信发送者身份、封禁状态和实例停止状态；访问控制不可用时不回复，mock 连接不执行真实诊断。
- 关闭开关时静默消费预留指令，不交给模型；AstrBot 会收到抑制默认 LLM 的终止动作。
- 直接在入站连接回复，不广播到其他连接；不附加普通群聊的自动 @/引用装饰。

## 版本来源

正式/预发布版本 tag 的官方 Docker 镜像显示去掉 `v` 的版本号，例如 `1.0.0`、`1.1.0-rc.1`。
main/latest 镜像显示构建 commit 前七位。本地源码编译始终显示 HEAD commit 前七位，即使当前检出了版本 tag；无构建元数据时显示 `unknown`。
运行期间不依赖 `.git`，也不向 GitHub 查询；给已有 commit 打 tag 不会修改已构建镜像，需运行 tag 工作流产出的新镜像。
具体注入和发布机制见 [构建版本说明](../../.github/build-version.md)。

## AstrBot 协议

后端与插件需一起升级（插件 0.1.5 起支持）。插件从当前顶层文本组件识别指令并发送布尔 `metadata.runtime_info_command`；后端同时验证正文与附件。旧插件扁平化的 `content` 可能来自引用，因此不能单独用它作为触发依据。

即使 `forward_all_group_messages=false`，这一精确指令仍会被转发；这是显式限定的诊断例外，不会附带引用历史或媒体。
插件在网络请求前抑制自身默认 LLM，断线、配置错误、发送失败、超时以及后端关闭/拒绝都不会退回模型回复。
